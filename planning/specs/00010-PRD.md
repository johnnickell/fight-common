# Deterministic Release Foundation

## Problem Statement

Release decisions currently exist only as planning contracts. Implementation needs one deterministic
command surface, immutable plans, resumable runs, machine results, evidence manifests, and safe seams
for external boundaries.

## Solution

Implement the framework behind `bin/release`: canonical JSON and digest rules, plan/run state, phase
handoffs, bounded logs, postcondition-driven resume, machine-readable results, and ports for Git,
signing, authorization, GitHub, and Packagist. Provide deterministic fakes, effect ledgers, and crash
points so the normal journey can be tested offline.

## Acceptance

- One narrow `bin/release` surface rejects capabilities outside the owning phase.
- Plans bind version, source and baseline OIDs, support policy, candidate inputs, evidence requirements,
  and approvals; changing a bound input produces a new identity.
- Every phase handoff contains the minimum machine-readable fields and one next action.
- Resume revalidates completed postconditions and never trusts a state label alone.
- Fakes and contract tests cover Git, signing, authorization, GitHub, and Packagist success, failure,
  uncertainty, and crash paths without credentials or external mutation.
- T-00032 is the first slice and proves plan creation and durable run state.

## Out of Scope

Real release publication, hosted configuration, actual signer identity, and operator-facing workflow prose.
