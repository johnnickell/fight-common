# Maintenance-Line and Patch Workflows

## Problem Statement

Supported-line maintenance must select affected lines from evidence, patch the oldest affected line
first, and forward-port through separately reviewed and certified steps without creating a hotfix bypass.

## Solution

Implement maintenance lifecycle and patch-line orchestration on top of the release lifecycle. Require
explicit affected, unaffected, or unknown evidence for every supported line, use the exact current tip
as the patch base, preserve EOL read-only behavior, and carry predecessor provenance through ordered
forward ports.

## Acceptance

- Unknown affected-line evidence stops before base-branch selection.
- The oldest affected supported line is selected first and each newer port is a separate reviewed,
  certified step.
- Urgency and security are metadata only and never bypass review, compatibility, certification, or
  authorization.
- Maintenance transitions preserve support-policy identity and make EOL lines read-only.
- Compatibility exceptions are exact, candidate-bound, and never reusable.
