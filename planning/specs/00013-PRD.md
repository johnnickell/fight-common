# Operator Surfaces and Release Integration

## Problem Statement

The release contracts need discoverable operator entry points that route to the correct phase and keep
policy single-sourced in repository commands and canonical planning documents.

## Solution

Add thin `.agents` skill entries, catalog routing, runbook journey cards, CI integration, and final
traceability validation. Operator surfaces inspect and classify state, request bounded approval, invoke
allowlisted commands, display postconditions, and expose one stop or next action; they do not own policy.

## Acceptance

- Six planned skills route to the canonical command and planning contracts without copying policy.
- The dispatcher routes by repository state, intent, affected lines, urgency, and release class.
- Journey cards cover feature, unreleased fix, supported-line patch, forward port, release,
  maintenance transition, and incomplete publication.
- CI and local verification use the agreed composed gate without duplicating release policy.
- Final traceability links the epic, PRDs, tickets, acceptance slices, and verification evidence.
