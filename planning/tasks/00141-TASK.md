## Validation and permissions

Amounts are signed native integers bounded by PHP_INT_MIN/PHP_INT_MAX; zero and negative amounts are valid. Parse
serialized integer text with range checks before native conversion, avoiding clamping/float promotion and a new 64-bit
floor. Numeric JSON amounts must not lose integer precision in downstream decoders: retain exact minor units as text
in supported versioned representation. Document PHP argument/type boundaries, not recovery of caller-side precision loss.

Fresh Money construction requires a supported accounting definition from the bounded Currency set, never a
default of two for an unsupported code or an arbitrary caller-supplied scale. Capture the definition/scale at
construction. Money owns the conversion between major Decimal amounts and minor units; consumers must not reconstruct meaning by reading
a newer Currency exponent. Exact conversion/scalar calculation rejects a fractional minor result unless a rounding
mode is explicitly supplied. Apply one exact rounding decision at the monetary boundary, not intermediate double
rounding. Zero divisors, unsupported precision and unrepresentable rounded/exact results fail predictably.

Identity reflects alphabetic currency, captured scale and minor-unit amount. Unrelated definition revision
metadata does not change equality/hash. Addition/subtraction and any amount comparison require compatible
currency/scale; reject mismatch instead of implicit currency conversion/rescaling or inferred exchange comparison.
Do not invent a global economic ordering of different currencies. Preserve existing shared ValueObject/collection
contracts; document owned identity if representation includes provenance beyond numeric identity.

Check final native representability without unrepresentable native intermediate operations. PHP_INT_MIN is valid;
its positive native negation is not. An exact wide internal calculation is not stored minor-unit overflow by itself.
Multiplication by one, cancellation and minimum-value allocation must remain valid; neither abs(PHP_INT_MIN) nor
native float round/casts can implement these guarantees. Scalar input uses exact supported numeric data, not floats.

Saved representation must be versioned/unambiguous and retain currency, exact amount, scale and enough supported
precision-definition context to preserve monetary meaning. Readers validate the saved definition/scale, not simply
replace it with a newer default. Retain supported reader definitions when definitions are updated or new codes
are added. Reject unknown/unsupported/tampered definitions or versions; do not guess precision, silently replace
currencies or redenominate. Final schema grammar/factory mechanics remain routine design within those backward-read promises; no existing consumer schema migration is required.

### Allocation contract

Accept a nonempty ordered list of nonnegative native integer weights, with at least one positive weight. Reject empty,
all-zero, negative, fractional/float and unsupported keyed inputs with DomainException; zero Money still validates the
input. Compute total weights/products and absolute amount with exact wide arithmetic even if intermediates exceed
native integer limits. A valid allocation must not fail only because array_sum/product/abs would promote to float.

Use largest remainder: calculate floor shares of the nonnegative exact magnitude, rank fractional remainders descending
and distribute leftover minor units, breaking ties by original list index. Restore the original sign, returning shares
in original input order with the same captured currency/scale. Zero weights receive zero; allocation of zero yields
zero shares. The signed shares sum exactly to the original amount, including PHP_INT_MIN; equal weighting covers the
split use case without requiring a separate convenience API or PR. This is deterministic arithmetic, not business
fairness, priority, payment execution or authority to distribute funds.

Invalid supported values, incompatible units, unavailable/unsupported precision, malformed reconstruction, allocation
validation and overflow raise documented DomainException failures. Native enum/argument errors remain documented;
do not blanket-wrap unrelated PHP Error or copy Novuso's exception/magic-constructor interface.
