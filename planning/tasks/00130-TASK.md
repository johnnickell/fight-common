## Scope

- In scope: make the existing final immutable StreamId implement Identifier, using ValueObject conventions where
  suitable, without imposing UUID-specific UniqueId or introducing a parallel opt-in stream-identity type.
- In scope: byte-preserving tuple equality, coherent hash/comparison, a stable unambiguous versioned ASCII string
  representation, fromString reconstruction and JSON exposure of that canonical representation.
- In scope: preserve public constructor/getters/nonempty invariants; delegate existing in-memory tuple comparison
  to the Domain-owned value without changing selected streams or storage parameters/fields.
- In scope: direct value and typed/hash/sorted collection evidence, existing in-memory/durable-store identity
  contracts, compatibility classification, docs/event-sourcing.md, relevant collection/value guidance and CONTEXT.md.
- Out of scope: special-casing collection hashing/equality to disguise
  its effect, persisted identity rewrites, new storage layouts/schema/collation, event-store concurrency or delivery
  changes, mapping/upcasting, aggregate ID redesign, general identity-framework reorganization, new dependencies,
  runtime deprecation warnings, packaging/release-process tests, certification or release operations.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Consumer compares separately constructed equal tuples | N/A; local identity operation | N/A; local comparison | N/A; no domain mutation | Equality and compareTo zero agree; hashes match regardless of object identity. |
| Consumer compares distinct tuples | N/A; local identity operation | N/A; local comparison | N/A; no domain mutation | Preserve both components in identity; order by aggregate name then identifier, bytewise. |
| Consumer reconstructs separator/control/binary components | N/A; value construction | N/A; local decoding | N/A; no domain mutation | Recover nonempty component bytes exactly from an unambiguous ASCII representation. |
| Consumer inserts equal tuples into a hash set/table | N/A; caller-owned collection operation | N/A; local collection access | N/A; no domain mutation | Tuple-equivalent membership/removal/key lookup and deduplication/replacement, with explicit minor-upgrade migration guidance. |
| Consumer uses typed Identifier or comparable sorted collections | N/A; caller-owned collection operation | N/A; local collection access | N/A; no domain mutation | Accept the existing Identifier capability and order consistently with equality. |
| Store/repository receives an existing stream tuple | Existing append unchanged; no new command type | Existing read/find unchanged; no new query type | Existing stored domain events unchanged | Select the same stream through unchanged component fields; no database/schema migration. |

Value operations have no I/O, new business messages or external effects. Existing EventStore/repository effects
retain their current owners and contracts. Collection mutation is caller-owned. A stream identifier establishes
identity, not authorization, existence, routing, permission or a UUID format requirement.

## Validation and permissions

Preserve constructor parameter names/signature and existing nonempty-component rejection/catchability. Do not add
trimming, case folding, numeric coercion, Unicode requirements or other restrictions to previously accepted nonempty
component strings. Local byte-string support does not claim every database/provider can store arbitrary bytes.

Use a stable versioned ASCII grammar that cannot confuse component boundaries; the approved example is
`stream:v1:<base64(name)>:<base64(id)>`. Final grammar details remain routine implementation design within this
unambiguous byte-preserving requirement. Reject malformed frames, unsupported versions, invalid encodings and empty
decoded components predictably with DomainException. Document accepted canonical spellings; distinct tuples cannot
collapse through delimiter concatenation or lossy Unicode handling. JSON exposes the canonical representation,
not a new replacement for persisted aggregate_name/aggregate_identifier fields.

Equality with a non-StreamId returns false. Comparison with a wrong type raises DomainException, rather than
relying solely on assertions that may be disabled. Within StreamId, compare aggregateName bytes first and identifier
bytes second; return a coherent comparison sign and zero exactly for equal tuples. Numeric-looking strings must not
be compared as numbers. Hash input must represent both components unambiguously; equal tuples have equal hashes.
Finite FastHasher digests are not promised collision-free, and collection equality must still distinguish different
values within a hash bucket. Preserve existing comparator-owned collection behavior where callers supply their own
comparator; do not rewrite the collection framework.

The approved minor exception covers automatic Equatable/Comparable/Stringable/JsonSerializable dispatch effects, including
set counts/membership/removal, equivalent table keys and native JSON changing from the current empty object to the
canonical value representation. Retain honest before/after evidence rather than calling these changes a signature-
compatible minor fix; delivery uses the explicit owner amendment above. Existing SQL parameters, tuple fields,
publication-failure diagnostic fields and stream lookup meaning remain unchanged under [ADR 0001](../adr/0001-event-sourcing-contract.md). Assess backward reading of supported
stored/serialized data under ADR 0011; exact PHP serialized bytes are not promised by implication.

Authorization remains consumer-owned. DomainException here does not become HTTP ResourceNotFound or a new
Application failure contract. Encoding is not redaction; the canonical representation can contain sensitive identity
data in recoverable form.
