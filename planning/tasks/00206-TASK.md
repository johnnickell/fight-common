# Deprecate public table-name constants for 2.0 removal

## Outcome and accepted decision

After merging TASK-00201's PR #291, John explicitly requested documentation-only deprecation of
`DbalSubscriptionSchema::TABLES` and every other public constant containing physical database table names,
with removal targeted for **v2.0.0**. This standalone follow-up does not reopen TASK-00201 or its acceptance.
John also requested removal of the entire authored `Current planning handoff` notes section from
`planning/tasks/BOARD.md`, leaving its routing index and generated task views intact.
The current request explicitly includes provisional constants as well as released constants; retain them
unchanged now rather than removing or renaming them under the general provisional-API rule.

## Scope

- Inventory public physical-table-name constants throughout shipped production code, including implicit-public
  constants, and annotate each with `@deprecated`, the v2.0.0 removal target and its actual replacement selection.
- Document the complete migration map and default-inventory versus configured-selection distinction; align
  current relevant consumer guidance and CONTEXT.md.
- Preserve constant names, visibility, types, values, internal uses and all existing runtime/schema behavior.
- Remove all authored `Current planning handoff` notes from the Board without removing routing instructions,
  generated sections or the owning TASK/TICKET/EPIC/Wayfinder records.
- Exclude removal, renaming, replacement alias constants, runtime notices, new configuration APIs, table/data
  migrations, unrelated constants and packaging/release-process tests.
