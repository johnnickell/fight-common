# Deliver the Combined Tools, Resources and Skills Journey

## Outcome

Deliver one coherent consumer composition of real Common Tools, document Resources and structured Skills through
the existing guarded MCP `2026-07-28` endpoint. A query-backed Tool returns a safe summary and standard Resource
link, the client reads that document revision, then discovers/gets a complete Skill entry and reads selected files.
Current injected authorization and consistent finite bounds protect the complete journey. Normally one PR owns
this integration and [TICKET-00030](../tickets/00030-TICKET.md)'s evidence mapping to EPIC-00007 completion.

## Scope

- In scope:
  - Explicit consumer composition of real Common Tool registration/invocation, shared document/Skill Resource
    providers, Skills list/get and the bounded existing HTTP handler, with truthful combined `server/discover`.
  - A package-owned read-only query-backed Tool fixture using existing Tool/QueryBus mechanics. It returns a safe
    summary and standard `resource_link` for an exact registered document revision, preserved through serialization.
  - Any necessary additive Resource-link semantic output/validation support, coordinated with the Tool owner and
    owned here rather than silently expanding TASK-00107. Reuse existing support if the delivered Tool API has it.
  - Complete document-link-to-read and Skill-list/get-to-selected-file journeys through the same real handler,
    with independent Tool/Resource decisions and whole-Skill availability rechecks at every relevant boundary.
  - Cross-capability validation of configuration/limits after JSON/Base64 expansion, current authorization,
    conservative private caches, central safe errors, diagnostics, guards and protocol mirrors.
  - Applicable pinned Resources/Skills server conformance against the composed endpoint, compatibility evidence,
    one consumer walkthrough and integrated TICKET/EPIC acceptance accounting, plus this slice's full gate.
- Out of scope:
  - Replacement Tool/Resource/Skill handlers, a hand-coded fake Tool protocol dispatcher, a second endpoint or a
    generic integration/plugin framework. Narrow extension merging and prerequisites already belong to TASK-00120.
  - Reimplementing request reading from TASK-00121 or capability-owned parsing, authorization and content budgets;
    this TASK qualifies their composition and owns only necessary bounded integration changes.
  - Actual planning search/Apply production APIs, business commands/events, Workflow mutations, catalog storage,
    permission/principal models, Agent OS/Pi implementation or production routes.
  - New framework adapters, SSE/cancellation, protected interactions, OAuth completion, directory RPC, rendering,
    execution, mandatory archives, release certification, publication, merge or deployment.

## Validation and permissions

Use real Common capabilities with explicit providers and one shared Resource method owner. Confirm Resources,
Skills and Tools advertisements match registration. Exercise duplicate methods/ambiguous Resource ownership,
conflicting extension settings and missing Skills prerequisites without adding alternate dispatch paths. Coordinate
Resource-link output with the Tool owner before freezing integration; preserve existing structured-output schema
and safe text/failure contracts rather than emitting arbitrary raw JSON from the Tool.

The Tool summary and link metadata must be deliberately public-safe under the injected consumer decision. A valid
link is not a read grant and need not appear in `resources/list`. Direct document reads use current Resource
availability independently of Tool availability. Skills discovery/get and every member read use current whole-Skill
authority, not a saved manifest, cursor, digest, authentication success or freshness hint. Vary decisions between
requests and private contexts without defining consumer permissions, principals or catalog policy in Common.

Preserve complete static manifests and exact revision identity. Verify raw bytes against manifest sizes/digests,
including Unicode/CRLF and binary encoding. Old addresses never silently substitute newer bytes. Listing/get does
not fetch files to complete entries; the fixture retrieves only `SKILL.md` and selected supporting content. Neither
templates/scripts nor nested `SKILL.md` content is rendered, executed or activated by serving it.

Qualify request-byte/decode limits from TASK-00121 together with capability-owned metadata, parsing, page, raw and
encoded response budgets. Accepted revisions/files must be retrievable within the declared composition after
JSON/Base64 expansion; unsafe override combinations fail without partial manifests or truncated success. Do not
add an unrelated blanket Tool-output quota or silently change existing Tool semantics to claim a unified limit.
Conservative private cache behavior cannot bypass current authority; deliberate public designation remains with
the consumer, not URI or content immutability.

Preserve Origin, invocation guard, authentication composition and standard/custom mirrors. Resource reads retain
the specified URI mirror; Skills methods acquire no invented `Mcp-Name` requirement. Rejected requests must not
open protected content. Selected-Tool `isError` outcomes remain distinct from Resource/Skill protocol failures;
unexpected errors are centrally sanitized and do not become empty success. Upstream authentication/PSR/server
buffering remains outside Common's bounded-reader guarantee; document rather than obscure that limit.
