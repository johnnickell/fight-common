# Configure publication storage and complete the customized journey

## Outcome

A consumer independently names publication cursor, publication failure and failed-handler tables, installs the
selected schemas and publishes committed events with unchanged cursor/failure guarantees. Complete an actual
Event Sourcing journey using all six configured tables together, consuming TASK-00194's Event Store/naming
mechanism and TASK-00195's configured checkpoints. This complete publication/integration slice normally owns one PR.

## Scope

In scope:

- Independent explicit overrides for `publication_cursors`, `publication_failures` and `publication_handler_failures`,
  preserving these exact defaults for omitted selections and released constructor/named-argument compatibility.
- Schema definition, explicit installation/existing checks, correct failure-to-handler foreign keys and associated
  schema objects, cursor load/save/monotonic update and duplicate-key recovery, atomic failure/handler persistence
  and retry handling using the chosen names.
- Reuse TASK-00194's Adapter identifier mechanism rather than creating alternate validation/quoting policy.
- Existing publication runner/dispatcher composition, cursor semantics, failure-record idempotence and error behavior.
- Extend the existing executable Event Sourcing journey with a configured-name variant that appends/reloads,
  projects/checkpoints and publishes/records failures across all six tables. Retain the default variant.
- Publication and complete six-table composition documentation, focused/conformance/journey tests and CONTEXT.md.

Out of scope: reimplementing supplier Event Store/checkpoint behavior, MCP/ORM conversion, automatic migrations,
renames/copies, qualified names, implicit global/environment configuration, new replay/reset operations, changed
failure payloads, stronger event-delivery guarantees or unrelated refactoring.

## Use cases and contracts

Actor: consumer integrator/operator, followed by the existing publication worker and synchronous subscribers.

| Use case | Commands | Queries | Events | Expected side effects |
| --- | --- | --- | --- | --- |
| Override one/all publication tables and explicitly install/reuse schemas | N/A: composition/deployment, not a bus Command | Existing schema inspection | None | Existing installers create selected storage when invoked, with valid configured failure/handler relationships |
| Resume publication and advance after completed fan-out | Existing EventPublicationRunner coordination; no new Command | Existing committed global polling and publication cursor load | Existing synchronous dispatch, unchanged | Monotonically update the configured publication-scoped cursor |
| Record failed subscribers or retry failure recording | Existing recorder operation | Existing storage checks, no new public Query | No new events | Atomically persist parent/handler rows under selected names, retaining first recorded evidence on retries |
| Handle storage/dispatcher infrastructure failures | Existing runner/recorder operations | Existing retry reads | Existing dispatch/error contract | Retain current rollback and cursor-not-advanced behavior where recording/fan-out completion fails |
| Run the complete customized Event Sourcing composition | Existing append, projection and publication paths | Existing stream/global/checkpoint/cursor reads | Existing event dispatch | Exercise real supplier and publication adapters with all six configured tables |
| Reject invalid names or change configuration | N/A: composition | No new public Query | None | Safe rejection or different storage selection; no migration/transfer of previous state |

Preserve [ADR 0002](../adr/0002-projection-delivery.md): publication cursors represent completed subscriber attempts,
not successful projection; recorded subscriber failures can permit advancement, while recorder/infrastructure
failure prevents it. A crash before advancement may repeat delivery; table naming adds neither exactly-once
processing nor automatic replay. [ADR 0001](../adr/0001-event-sourcing-contract.md)'s committed event order is supplied
by TASK-00194, not redefined by this TASK.

## Validation and permissions

Use the supplied ordinary-identifier validation and platform quoting for runtime SQL and schema/foreign-key
references, retaining data binding. Reject unsafe/unsupported/qualified selections without SQL interpretation or
fallback. Omitted overrides intentionally retain defaults; explicit overrides must never accidentally select them.
Preserve the finite existing DBAL 4.4 schema-construction compatibility exception without expanding suppressions.

Consumers retain composition, database privileges, worker/retry policy and subscriber authority. Naming supplies
no new permission or public endpoint. Keep current diagnostic/failure snapshots, transaction atomicity, correlation
identity and safe exception boundaries. Changing a table does not prove old failures/cursors were migrated or
that previously delivered events are safe to redispatch.
