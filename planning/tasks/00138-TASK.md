## Validation and permissions

Use TASK-00136's supported exact zoned/instant capability. Validate start <= end by instant only, not its timezone-
aware value comparator's tie-breaker. For nonempty intervals, containment is start <= candidate < end. Equal instants
are empty even when DateTime equality is false because identifiers differ; no instant, including either endpoint,
belongs to an empty interval. Never silently swap reversed endpoints or truncate microseconds.

Identity is the ordered pair of exact instant endpoints. Ranges with the same endpoint instants have equal hashes
and compare equal regardless of endpoint zones; distinct endpoint pairs remain distinguishable, including empty
intervals located at different instants. This is endpoint identity, not general set-theoretic equivalence. Reuse
DateTime-owned instant semantics/native interoperability; do not duplicate DST interpretation in the range.

String/JSON reconstruction must retain both exact instant endpoints, supported precision/bounds and the half-open
meaning without ambiguous delimiters or dependence on ambient timezone. Codec/getter/zone-label retention mechanics
remain routine design; timezone labels, if retained as endpoint context, cannot change equality/hash/containment.
InstantRange owns this instant-based identity rather than changing global ValueObject or DateTime equality. Document
how representation and endpoint context relate to equality, rather than silently inheriting timezone-sensitive
endpoint hashes or implying that equal ranges must retain the same original zone labels.

Malformed/unsupported representations and reversed intervals raise DomainException. Native/type-boundary behavior
remains documented under the supported API. Do not add arbitrary span caps, a universal duration-length requirement,
a new platform floor or lookup permission policy. Preserve AuditRepository's inclusive native contract separately.
