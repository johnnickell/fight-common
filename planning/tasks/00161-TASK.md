# Recover retained notices through shared Queries and MCP

## Outcome

Authorized callers can recover retained notices in bounded batches through a shared Query and an explicitly
registered MCP polling Tool, with honest continuation and complete/incomplete/uncertain outcomes. Deliver recording
→ failed publication → recovery and removal/concurrent-change behavior together in one normal PR, without live streams.

### Approved recovery mechanics

Read dedicated notice storage in ascending committed notice-position order, using TASK-00158's commit-order guarantee
and TASK-00159's bounded history-loss evidence. This is distinct from TASK-00160's stateless page/per-page history
inspection and MCP catalog pagination. No timestamp/UUID shortcut or Event Store/projection dependency is introduced.
Document ordering scope and the boundary actually examined; no global order across unrelated stores is presumed.

Use bounded opaque continuation protected against tampering and disclosure of concealed metadata. Bind it to the
relevant selection/serving context and assess current access each call. Possession confers no authority; changed
selection or cross-caller reuse must not silently continue a different history with a complete claim. Do not expose
raw global counters or concealed scopes/activity through token contents or public gap details. Base64 encoding or
authentication alone is not confidentiality. Exact representation, key/configuration requirements, finite lifetime
where applicable and restart/error mapping are implementation details to document and test, without a new principal
model, remembered browser search or server-side processing-acknowledgment ledger.

Separate bounded-batch continuation from recovery completeness. A complete claim means the qualified interval
through the identified committed boundary was exhausted under demonstrated selection/access/history conditions;
it does not mean future notices cannot arrive, all originating application changes were recorded, or returned notices
were received/processed. Establish the actual evidence for each claim. An empty page alone is insufficient; finite
scan exhaustion, unavailable history evidence and unproven access continuity must not become complete success.
Define initial/start/restart, multi-batch and subsequent-poll behavior without a frozen result or retention lease.

Reauthorize every call. If continuity of selection/access cannot be established, report uncertainty or require a
restart; a current positive permission decision does not prove historical permission stability. Consumer composition
owns trustworthy access context, not an argument asserting an unchanged policy. Returning newly permitted data must
not silently skip older newly eligible notices by treating an old continuation as complete. Revocation cannot be
bypassed by prior results/tokens, and already returned bytes cannot be retracted by this library.

Assess selected rows, the examined committed boundary and history-loss evidence coherently under concurrent removal.
Removal between batches, deletion of the last notice, retirement/unavailability of loss evidence and concurrent
recording require honest complete/incomplete/uncertain outcomes. Conservative uncertainty is permitted where proof
is unavailable; explicit expiry requires evidence rather than inference from a missing row. Report safe limits,
not concealed counts/relationships or deleted notice bodies. Define the observation point and consistency guarantees;
no promise extends beyond the state actually assessed or preserves data for a future continuation request.

### Bounded MCP presentation

Explicitly register the polling Tool on the existing guarded HTTP composition. Tool availability and Query access
are separate current decisions; request arguments/metadata, references and endpoint admission are not trusted grants.
The Tool uses shared Queries, never direct adapter SQL, a competing filter or a duplicate completeness policy.

Bound selection/continuation inputs, scanned work, batches, notice/reference output and the actual encoded response.
Never advance continuation past an omitted eligible notice. If an individual notice or result cannot fit, return a
safe explicit failure or another documented bounded outcome that preserves recovery, not silent dropping/truncation
or empty success. Include structured content, its compatible text companion, escaping, applicable central metadata
and outer protocol envelope overhead. Output-schema validation and `McpToolOutput` JSON safety alone do not bound
final bytes; existing `McpResult::boundedComplete()` bounds the result but not its outer JSON-RPC envelope. Prove the
actual composition. Any shared seam changes need compatibility classification; unfinished introspection/Prompt
presentation work is not a prerequisite. Exact Tool/schema/API names and numeric budgets remain implementation details.
