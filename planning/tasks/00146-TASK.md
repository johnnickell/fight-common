# Make Hosted CI Advisory for Fight Common PR Delivery

## Outcome

Fight Common's live contributor and agent guidance follows John's 2026-10-09 decision: hosted CI results
inform human PR merge discretion, not a mandatory pass condition for agent landing or human merge unless a
separately accepted TASK requirement or actual host rule makes a check mandatory. Keep the local full product
gate, independent review and applicable QA intact. This is a separate policy PR from Decimal/TASK-00139;
no code, CI configuration or prior PR acceptance is changed by this TASK.

John explicitly stated that this project has never required hosted CI to pass before merge and instructed us
to change any project instruction imposing that condition. He approved an isolated worktree for this separate
policy change on 2026-10-09. The current profile and ADR 0008 incorrectly require successful final-head
Tests and Deploy Docs for delivery; ADR 0028 calls release-PR hosted checks required. GitHub's develop
ruleset, inspected at this checkpoint, has no required status-check rule (it requires a PR/merge commits).

## Scope

- In scope: project profile, ADR 0008 and release ADR 0028, related adopted instructions/adoption record,
  with clear readiness/human discretion, accurate failed-check reporting and real host-protection precedence.
- In scope: distinguish optional CI outcomes from required local build, independent technical review, applicable
  QA, signed release certification and explicit human merge/release authority; leave historical checkpoints true.
- Out of scope: changing CI workflows/rulesets, bypassing an actual host-enforced check, retroactively calling
  failed runs green, altering TASK-00139 code/review/QA or publishing/merging either PR under this work request.

## Validation and permissions

An optional failed, skipped, missing or unreadable hosted job is **not** a pass and must be disclosed and
classified. A demonstrated product failure invalidates applicable acceptance; missing required local evidence,
independent review or QA still blocks landing. Explicit accepted TASK-specific hosted gates and actual host rules
retain their force. This policy grants no agent PR merge, force-push, release or deployment authority. No request
actor/permission handling or application runtime changes apply.

## Acceptance criteria

- [x] Active project instructions and ADRs consistently place hosted CI under human merge discretion by default,
  without a final-head success gate for ordinary Fight Common PR landing; retain workflows as useful evidence.
- [x] Preserve mandatory local `./bin/build`/documentation equivalence, independent review, applicable QA,

- [x] Reconcile release-PR wording without weakening separately authorized exact-commit release certification,

- [x] Keep historical decisions/receipts intact; check links, generated planning views and local checks directly,
