# Add and adopt the Base64URL helpers

## Outcome

Callers can encode and decode Base64URL through shared Domain functions without changing existing consumer formats.

## Scope

Add `Fight\Common\Domain\base64_url_encode()` and `base64_url_decode()`. Adopt them only where output bytes, accepted inputs and caller-level failures are equivalent. Do not replace standard Base64 or integrity and protocol checks.

## Use cases and contracts

Caller supplies bytes or encoded text. Pure functions return unpadded Base64URL, decoded bytes, or `false` for invalid input. No queries, events, permissions or external state.

## Validation and permissions

Use `+` to `-` and `/` to `_` on encode, reverse on decode. Accept empty input and optional correct padding only; reject extra or partial padding, whitespace, standard alphabet substitutions, impossible lengths and noncanonical trailing bits.

## Acceptance criteria

- [x] Direct tests cover canonical vectors, binary and empty round trips, correct padding and malformed forms.
- [x] Any migrated caller has equivalence evidence for wire/storage and failure behavior; non-equivalent callers are left unchanged.

## Verification and evidence

Run focused Domain and affected caller tests and `./bin/build` with exact Unit coverage. Record interoperability vectors and consumer surface updates.

## Completion notes

The two Domain functions are additive public Composer-autoloaded APIs, classified in
`compatibility/manifest.json`. See [Base64URL helpers](../../../docs/values.md#base64url-helpers) for the contract and
interoperability vectors. TASK-00229 can carry this forward as an opt-in addition; existing consumers need no
configuration, wire-format or storage migration for this TASK.

- MCP Prompt, Resource, Skill and Tool discovery now share the encoder. Each cursor still encodes the same
  four-byte offset plus 32-byte binary signature. Base64 of those 36 bytes has no padding to strip, so the
  emitted 48 characters are unchanged. Cursor decoding and all caller checks are unchanged: the protocol
  already validates the exact alphabet and length, which leaves no padding or unused bits to check again.
- MCP Sodium interaction state now shares both helpers. The token grammar still excludes padding, standard
  alphabet characters and whitespace; the decoder's encode-and-compare check replaces the adapter's former
  unpadded round-trip check for that grammar. Prefix, size, key, minimum payload length, authentication and
  `Invalid interaction state.` failure remain unchanged.
- Standard Base64 stays unchanged for Notice recovery ciphertext, MCP headers, image data and byte chunks or
  resource blobs, stream identities, and zoned date-time/instant-range storage. Their wire or storage alphabets
  and padding contracts are not interchangeable with Base64URL.
