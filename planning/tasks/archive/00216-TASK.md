# Make the public docs easier to use and show the stable release

## Outcome

A reader can tell what Fight Common does, install it, and find the right guide without knowing the library’s architecture first. The repository README shows the latest published stable release and links to its notes without a manual version edit.

## Scope

- Simplify the [README](../../../README.md), [docs homepage](../../../docs/README.md), and [Quick Start](../../../docs/quickstart.md). Use familiar words, short sentences, and brief explanations of necessary technical terms. Aim for a high-school reading level for the prose, not for the PHP examples.
- Simplify the [site menu](../../../mkdocs.yml). Give Quick Start priority, make Components and Frameworks easy to find, and group related MCP task, notice, and subscription guides. Keep existing page URLs and bookmarks working.
- Add a Stable release badge alongside Tests, PHP, and License. Update the existing [README validator](../../../scripts/validate_readme.py) and [release checklist](../../../release/README.md).
- No broad rewrite of component guides, runtime or API changes, release version changes, tagging, or publication.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| A new reader opens the README or docs site to get started | Existing Composer install command, run by the reader | Follow the Quick Start, component, or framework link | N/A; docs only | No project change from browsing |
| A reader checks the current stable version | N/A | Read the badge and open the latest published stable release notes | N/A; no application events | The badge follows the published release without a README edit |
| A maintainer prepares or verifies a release | Existing docs validator and release checklist | Check the badge against GitHub’s published stable release before shipping and after publication | N/A; checks do not publish | Local validation rejects missing or incorrect badge markup; live verification records any mismatch or unavailable result |

## Validation and permissions

Validate the badge and its destination locally without network access. The maintainer’s live check is read-only and does not replace certification or grant release authority. If the live badge or release cannot be verified, report the check as unverified, not passed. No application permissions, schema, or data changes are needed.

## Acceptance criteria

- [ ] The README explains the library in plain language, offers one clear set of starting links, and routes readers to the existing migration and compatibility guides without losing published guarantees.
- [ ] Quick Start puts PHP 8.5+, Composer, and `composer require johnnickell/fight-common` before the starter repository previews. Keep the starter release warning, runnable examples, and the explanation that the event follows a successful database commit.
- [ ] From the homepage and mobile and desktop menus, readers can find Quick Start, Components, and Frameworks without opening unrelated groups. Related MCP guides are grouped and existing page URLs and anchors still work.
- [ ] The README shows a Stable release badge linked to the release notes for GitHub’s latest published stable release. At planning, this was `v1.5.1`; do not hard-code it. A draft, prerelease, or older-line patch must not displace the current stable release. The other three badges still work.
- [ ] The README validator rejects a missing, duplicated, or mislinked Stable release badge offline. The release checklist verifies before shipping that the badge still shows the current stable release, then verifies after publication that it updates for a new latest stable release or stays unchanged for an older-line patch. It does not require a release to be published to finish this task.
