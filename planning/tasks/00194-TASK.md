# Configure Event Store and sequence table names

## Outcome

A consumer explicitly configures the Event Store's event and global-position table names, installs their schema
and appends/reloads history through the existing public contracts. Establish reusable Adapter-owned ordinary
identifier validation/quoting through this working persistence path, not an interface-only foundation. This TASK
normally owns one PR and supplies the naming mechanism used by TASK-00195 and TASK-00196.

## Scope

In scope:

- Independently configurable `event_store_events` and `event_store_global_position`, with exact current defaults
  for omitted overrides and explicit schema/runtime composition.
- Schema definition, explicit installation/initialization and existing schema checks; append, sequence locking,
  stream/global reads, stream version and every retry/conflict lookup using the selected names.
- Reusable safe identifier validation/quoting at the Adapter boundary, designed for the demonstrated Event Sourcing
  consumers. Exact classes, configuration signatures and grammar/limits are implementation design, not a new
  Domain/Application contract or global settings registry.
- Preserve default construction and released named parameters, index/uniqueness semantics, stored data formats,
  mapper behavior, transaction/retry guarantees and supported DBAL/platform ranges.
- Relevant consumer documentation, tests and CONTEXT.md alignment.

Out of scope: projection/publication adapter conversion (TASK-00195/00196), MCP/ORM conversion, migrations,
automatic renames/data transfer, schema-qualified names, implicit environment/global configuration, column/event
schema changes, new transaction policy, namespace refactors or mandatory prefixes.

## Use cases and contracts

Actor: consumer integrator/operator at composition/deployment, then an existing application caller.

| Use case | Commands | Queries | Events | Expected side effects |
| --- | --- | --- | --- | --- |
| Select one/both names and explicitly install or reuse selected storage | N/A: composition/deployment, not a bus Command | Existing schema inspection | None | Existing installer creates/initializes only selected storage; configuration alone performs no DDL |
| Save/reload event history | Existing aggregate save/Event Store append; no new Command | Existing stream/global/version reads | Existing event recording/publication contracts, unchanged | Append events and serialize global positions through selected tables |
| Retry after conflict or uncertain acknowledgment | Existing append operation | Existing identity/version/retry lookups | No new event behavior | Preserve exact-retry success or conflict rejection without duplicate appends |
| Supply invalid/unsupported names or choose another name | N/A: composition | No new public Query | None | Reject safely, or select different storage without moving existing data |

Preserve [ADR 0001](../adr/0001-event-sourcing-contract.md)'s expected-version, message identity, metadata snapshot
and prefix-stable commit visibility guarantees and [ADR 0011](../adr/0011-non-structural-compatibility-policy.md)'s
released API/data compatibility. Physical names do not change aggregate/event aliases or stream identity.

## Validation and permissions

Validate ordinary identifiers and apply platform-appropriate identifier quoting in schema/runtime paths. Reject
unsafe/unsupported/qualified names without SQL interpretation or silent default fallback; retain value binding.
Document grammar/limits and deliberate collision handling. Keep raw logical names and SQL identifiers coherent
without exposing quoting mechanics inward. Preserve the finite DBAL 4.4 schema compatibility exception in the
[profile](../agents/project-profile.md#approved-dbal-schema-compatibility-exception), not new blanket suppressions.

Configuration is supplied by trusted consumer composition, not request input or authorization. Consumers retain
connection/schema selection, database privileges and application permissions. Preserve existing missing-storage,
installation, transaction, rollback and retry/error boundaries; no configuration change claims data migration or
resolution of commit uncertainty.

## Acceptance criteria

- [ ] Both tables are independently configurable, including event-only and sequence-only overrides. Omitted
  selections intentionally use existing defaults; overridden logical tables never fall back to their default names.
- [ ] Default public construction/named arguments and existing supported stored records remain functional.
- [ ] Schema generation/install/initialization and all append/read/retry/locking paths agree on the selections.
  Existing installer idempotency and uniqueness/index behavior remain intact.
- [ ] Safe reusable Adapter identifier handling is implemented and exercised by real Event Store operations;
  invalid/unsupported/qualified names reject without SQL execution as fragments or fallback.
- [ ] SQLite, MySQL-compatible and PostgreSQL evidence proves round trips, exact retries, conflicting identities,
  expected-version failures and concurrent prefix-stable committed global ordering with configured names.
- [ ] Populated default tables coexist in focused isolation probes without reads/writes for their overridden
  logical counterparts. Partial-override probes distinguish intentionally retained defaults from accidental fallback.
- [ ] Changing configuration performs no table/data rename, migration or copy; missing/incompatible selected
  storage retains the current explicit installation/error boundaries rather than secretly selecting old storage.
- [ ] Documentation explains both defaults, partial overrides, shared installer/runtime composition, identifier
  restrictions and no-migration consequences; affected CONTEXT.md descriptions match implementation.
- [ ] Required local verification, independent Review acceptance and required QA are satisfied before `done`.
