# Configure subscription storage and complete live integration

## Outcome

Consumers independently name subscription registration/state tables and run existing registration, renewal, closure,
expiry, cleanup and inspection operations against them. Complete existing actual live subscription/Task journeys
using configured Task and Notice suppliers as well as configured subscriptions. This complete persistence/live
integration slice normally owns one PR and completes the eight DBAL tables owned by TICKET-00055.

## Scope

In scope:

- Independent overrides for `fight_mcp_subscription_state` and `fight_mcp_subscriptions`, with exact defaults for
  omitted selections and compatible public construction/named parameters.
- Schema definition/install/validation/initialization, state version/serialization locking, capacity counts,
  registration writes, heartbeat/renewal, closure, expiry/cleanup and subscriber read/scan/count SQL using selected names.
- Reuse TASK-00194's safe Adapter identifier handling; share explicit schema/store/reader composition rather than
  introducing global/environment configuration or inward naming contracts.
- Preserve owner/registration identity, current disclosure grants, context bounds, lifecycle timing, active/total
  capacity, bounded inspection, terminal storage failure behavior and best-effort delivery semantics.
- Extend existing actual live subscription and live Task fixtures/HTTP journeys with configured subscription,
  Notice and Task tables, independent producer/reader processes and retained default variants.
- Relevant consumer docs, complete eight-table lifecycle inventory and CONTEXT.md alignment.

Out of scope: reimplementing Task/Notice suppliers, new subscription protocols/filters/transports, stronger delivery
or execution guarantees, changed permissions, ORM naming APIs, unrelated refactors, mandatory prefixes, qualified
names, migrations, automatic renames/data transfer or runtime schema installation.

## Validation and permissions

Apply shared ordinary-name validation/quoting to schema, state locks, counts, lifecycle SQL and subscriber reads;
keep values bound and reject unsafe/unsupported/qualified selections without interpretation or fallback. Names are
trusted consumer composition inputs, never request-controlled routing or authorization.

Keep registration owner, subscriber-inspection, generic change-feed and Task-specific disclosure decisions distinct.
Generic subscription access is not Task result/input permission. Preserve fresh permission checks, concealed context,
protected-state exclusion from general retained Notices and safe failure projection. Naming changes neither renew
expiry nor prove an event was delivered/processed. Preserve committed-read isolation/version checks and uncertain
storage/source/transport failures; changing tables does not imply migration or graceful live completion.
