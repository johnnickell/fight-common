## Evidence and affected scope

User supplied the result of a real Symfony-kernel probe against Common **v1.4.1**: one rendering failure is safe;
repeated primary/fallback failures escape as a diagnostic-bearing exception. The artifact/command is not yet
attached to this record and was not rerun by this intake. This proves the reported containment gap, **not deployed
application exposure or a production exploit**; retain those limits and original probe provenance during Work.

Source corroboration: `SafeErrorController::handle()` catches primary report/map/project/response creation, then
calls `SafeHttpErrorPolicy::fallback()` and `Symfony\JSendResponse::fromEnvelope()` outside the catch. That factory
calls the fallible `JSendEnvelope::toJson()`. A second fault escapes before the exception subscriber sets a response.
The same flow exists in canonical 1.4.0/1.4.1 and the current 1.5 candidate; current differences are property naming.
The safe controller/subscriber/policy are absent from pre-1.4 tagged releases; that is capability/source evidence,
not a runtime qualification of legacy handlers. Establish the focused affected-line matrix before claiming it final.

| PSR-15 safe JSend middleware | Catches terminal failure and throws fixed sanitized RuntimeException without a previous cause, as documented; no raw fallback diagnostic escape found; do not replace its broken-factory contract with an impossible guaranteed response |
