# Discover and Get Complete Authorized Skill Entries

## Outcome

A client discovers complete authorized Skill entries, directly resolves a served `SKILL.md` URI independently of
listing membership, and retrieves selected verified revision files through the existing guarded endpoint. Deliver
`skills/list` and `skills/get` together before advertising `io.modelcontextprotocol/skills`, completing
[TICKET-00029](../tickets/00029-TICKET.md) over MCP `2026-07-28`. This is a complete extension use case, normally
one PR, not a later testing phase for [TASK-00119](00119-TASK.md).

## Scope

- In scope:
  - A Skills capability using TASK-00119's validated immutable revisions, manifest representation and shared
    Resource file serving. Both list and get return the same complete entry shape with full frontmatter.
  - Current whole-Skill availability, deterministic filtered pagination with atomic entries, and exact direct get
    without requiring a previous listing or assuming an absent entry is denied.
  - Complete protocol result/cache fields, finite request/entry/page/encoded-response bounds and validated
    overrides consistent with the revision and Resource limits; conservative private cache behavior.
  - Truthful extension advertisement under `extensions`, with list/get and readable Resources prerequisites
    enforced at composition. Preserve independent Resources use and no directory/subscription notification claims.
  - Narrow registry extension-ID composition: distinct IDs coexist; identical same-ID settings may coalesce;
    contradictory same-ID settings and duplicate method ownership fail. No generic plugin framework.
  - A real guarded endpoint discovery/get/selected-file-read journey, applicable pinned server Skills conformance,
    compatibility classification, consumer walkthrough and full TICKET acceptance mapping.
- Out of scope:
  - Reimplementing snapshot validation/parsing, Resource handlers, the HTTP endpoint or consumer authentication.
  - Directory RPC, dynamic Skills, URI-template resolution, server rendering/execution, archive-required retrieval,
    subscriptions/listChanged, federation and automatic network/filesystem discovery.
  - Consumer permission/principal/catalog policy, persistence/publication lifecycle, Agent OS or Pi implementation,
    client activation/consent/cache/session management, new business messages and schema migrations.
  - Tool Resource links, combined Tools/Resources/Skills acceptance and shared bounded HTTP body reading, owned
    by [TICKET-00030](../tickets/00030-TICKET.md). No new framework adapter, release or deployment.

## Validation and permissions

Advertise the stable Skills identifier only with both `skills/list` and `skills/get`, the Resources capability and
readable revision files. Fail incomplete composition rather than publish an unusable extension. Merge only distinct
extension IDs (or identical same-ID settings); reject conflicting same-ID settings and duplicate methods while
preserving other existing registry contracts. Ordinary Resources remain usable without Skills.

Return every authored JSON-representable frontmatter field and every manifest member exactly as validated by
TASK-00119. List entries are complete, not summaries needing get; one entry cannot be split across pages or have
members redacted for caller-specific access. Preserve exact revision URI, sizes and digests without normalizing
bytes. Multiple valid entries sharing a display/name value are not silently collapsed; use exact URI identity.

Apply the current injected whole-Skill decision before exposing entries and before pagination. Direct get must
resolve availability independently of prior page membership and reuse the same decision semantics as file reads.
No principal, permission vocabulary or Agent OS catalog policy enters Common. URI/cursor/hash possession,
authentication and cache freshness are not authorization; private reuse must not cross authorization contexts.

Validate list/get parameter shapes, exact served root URIs, cursor syntax/scope/size and complete provider output.
Preserve protocol-valid values and terminate pagination by absence of `nextCursor`, not truthiness. Restart safely
when a continuation cannot be honored; do not promise a changing catalog is a cross-page snapshot or require new
human approval for routine recovery. Use finite validated entry/page/encoded bounds without truncating an atomic
manifest, and ensure accepted revisions remain retrievable within the combined limits. Routine discovery/get
uses validated metadata without reopening/re-hashing every file on every request.

Unknown/unavailable direct get returns the same safe central invalid-parameters outcome; unexpected failures use
generic internal errors with sanitized diagnostics, not Tool `isError` or an invented client-integrity wire error.
Return required cache fields with conservative private defaults and validated consumer overrides. Preserve the
existing Resource URI mirror and Origin/guard/authentication composition; do not invent a `Mcp-Name` requirement
for Skills methods. Serving an unadvertised directory RPC or assuming `allowed-tools` is an execution grant is out
of scope.
