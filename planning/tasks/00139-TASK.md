# Add Exact Decimal Arithmetic

## Outcome

Consumers parse, compare, calculate and explicitly round exact decimal values without binary-floating-point
approximation. Deliver immutable Decimal and complete precision/rounding/reconstruction evidence and documentation
in one independently reviewable PR under [TICKET-00037](../tickets/00037-TICKET.md) and
[EPIC-00008](../epics/00008-EPIC.md).

John approved this code-first feature TASK and its contracts on 2026-10-06. It has no TASK blockers or execution
priority and is independent of Currency/TASK-00140. Money/TASK-00141 depends on both. This is additive next-minor
scope subject to actual compatibility assessment, not an exact version or implementation/release authorization.

## Scope

- In scope: final immutable Decimal under Domain/Value, preferably Basic/Decimal, named string construction,
  normalized exact representation, numeric equality/hash/Comparable behavior and string/JSON reconstruction.
- In scope: exact addition/subtraction/multiplication, finite exact division, explicitly scaled/rounded division
  and rounding using PHP's native RoundingMode, with documented precision/input bounds and predictable failures.
- In scope: plain-PHP exact baseline, meaningful product/value/rounding tests, public/behavioral classification,
  docs/values.md and CONTEXT.md, full verification and independent review.
- Out of scope: floats as a financial factory/backend, scientific notation, localized parsing/formatting,
  unlimited precision promises, arbitrary rational storage, required BCMath/GMP/third-party arithmetic dependencies,
  new platform floors, global bcscale changes, Currency/Money policy, new persistence/helpers and release-process tests.

## Validation and permissions

Use whole-string ASCII plain decimal syntax with an optional sign, required integer digits and optional nonempty
fractional digits; reject exponent notation, separators, surrounding whitespace and unsupported syntax. Provide no
float factory or binary-floating-point financial calculation. Document supported PHP argument/type boundaries;
prior caller-side precision loss cannot be recovered by a string factory.

Normalize leading integer zeros, redundant fractional trailing zeros, the positive sign and negative zero.
`1`, `1.0` and `+01.000` represent the same numeric value; zero is canonical `0`. The accepted value bounds are at
most 1,024 normalized coefficient digits and normalized scale 0–1,024, with at most 4 KiB (4,096 bytes) of input.
Requested result/rounding scales are also 0–1,024. Check raw input length and supported normalized value/result
bounds rather than silently truncating, rounding to fit or casting a huge coefficient to a native integer.
A requested scale controls numeric precision, not preservation of insignificant zeros in canonical identity.

Exact operations must either return the exact supported result or reject. Exact division rejects zero, a
nonterminating decimal expansion or a result outside supported bounds. A separate scaled/rounded operation requires
both explicit output scale and native RoundingMode; no default mode authorizes lossy calculation. Implement all eight
native modes on exact decimal data, including signed half ties, parity and directed rounding; native float round()
is not an arithmetic backend. Internal representation/factory spellings remain routine design within these promises.

Use same-concrete-type canonical numeric equality/hash and numeric comparison returning -1/0/1, coherent with equality.
Wrong-type equality is false; invalid supported value input, requested scale, division/result precision or wrong-type
value comparison raises DomainException. Document native enum/argument type failures without promising to wrap every
PHP Error or altering shared ValueObject/Comparable behavior.

Current Domain dependencies permit only Domain/PHP internals. Composer platform emulation for BCMath and an incidental
vendor/brick/math installation do not authorize a required extension or external Domain backend. The supported
baseline must work without BCMath/GMP and without changing locale, floating-point settings or process-wide scale.
