# Qualify progressive MCP in every supported framework starter

## Outcome

Complete TICKET-00025's adopted framework-support evidence after TASK-00109 produces an exact Fight Common
candidate. Each of the five framework starter repositories owns a local vertical TASK and PR that installs that
candidate, composes its own route and runtime, proves live progress/failure/disconnect behavior in a booted journey,
and commits an eligible support receipt. Fight Common then records immutable receipt pins and closes integrated
acceptance without moving consumer composition into the package.

## Scope

- In scope:
  - Allocate one local TASK/PR in each starter repository after its owner accepts the cross-repository plan:
    `johnnickell/project-symfony`, `johnnickell/project-laravel`, `johnnickell/project-yii`,
    `johnnickell/project-codeigniter`, and `johnnickell/project-slim`.
  - Each starter installs the exact TASK-00109 Fight Common candidate, owns its route, service/container wiring,
    native response/runtime configuration, buffering settings, disconnect observation, and booted client journey.
  - Each starter proves multi-event success, expected and unexpected failure after progress, no-token direct JSON,
    early disconnect/no later bytes, and its canonical `./bin/build` and `./bin/planning-check` gates.
  - Each starter updates its `evidence/framework-support/receipt-v1.json` canonical support receipt, or first
    reconciles any repository-local relocated path with the adopted Common policy and immutable receipt references.
  - Fight Common validates and records immutable repository, exact 40-character commit, canonical receipt path,
    receipt SHA-256, exact candidate identity, and successful journey/build state for all five starters.
  - TICKET-level evidence reconciliation, affected Common documentation, generated views, and the complete local
    planning/build evidence required for this coordination TASK.
- Out of scope:
  - Reimplementing TASK-00108 reporter semantics or TASK-00109 package HTTP/SSE adapters in a starter.
  - A sixth framework-free starter. The concrete framework-free runtime is package-owned and proven by TASK-00109.
  - Publishing, merging, releasing, or deploying any repository merely because this planning record exists.
  - Weakening the adopted requirement for both library adapter conformance and a booted installed-package journey.

## Validation and permissions

Each starter owns its route, authentication, authorization, service/container configuration, PHP SAPI/server,
framework response, output buffering, proxy settings, and runtime lifecycle. Fight Common owns the shared package
contract and receipt reconciliation only. A starter must consume the exact candidate by a reviewable Composer
reference; copied source or an unrelated released version is not evidence.

The booted client must observe at least two progress messages before final completion. Every journey records actual
event read boundaries or timestamps, final termination, response headers, framework/runtime versions, buffering
conditions, expected/unexpected failure behavior, and disconnect suppression. A callback, in-memory body, adapter
unit test, or TASK-00109 package fixture cannot substitute for the installed-package journey.

The adopted receipt policy fails closed. Each eligible receipt identifies its candidate, selected capability,
booted journeys, build/planning evidence, result, and exact content. A non-passed state retains one resumable action.
Fight Common records only immutable commits and verified receipt digests. No support claim is inferred from a
Composer constraint or a framework repository existing.

In Fight Common, validate the five immutable pins, receipt schema/digests/candidate identity, and complete journey
matrix, then run focused receipt/planning checks and the canonical gate appropriate to any implementation or build
input changed here. Save reconciliation evidence under this TASK's ignored run directory. No hosted CI pass,
merge, release, or deployment is implied by a local build receipt.

## Coordination and decision

Recommended decision: preserve the adopted uniform support policy. After TASK-00109 yields a candidate, create one
local vertical TASK/PR from `develop` in each starter, run the five journeys independently against that candidate,
then return immutable receipts to this parent TASK. Dependency/merge order is TASK-00108, TASK-00109 candidate,
five independently owned starter changes, then Common receipt reconciliation and TICKET closure. A starter may not
merge against an ambiguous package state, and Common may not close acceptance before all five receipts qualify.

Changing the policy to accept package conformance without starter journeys would be a separate governance decision
under ADR 0024 and the adopted support policy; it is not assumed here. This TASK remains `needs-info` until the
recommended cross-repository allocation is explicitly authorized and the five local TASK IDs, branches, and
candidate-consumption plan are recorded.
