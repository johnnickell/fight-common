# Clarify execution and Notice domain building blocks and identities

## Outcome

Make recent execution/Notice Domain types recognizable aggregates, identities, nested entities, values or messages;
remove technical helpers/receipt-only wrappers from Domain. Values extend the existing ValueObject hierarchy.
John accepted this correction on 2026-11-02. Normally one behavior-preserving domain-classification PR; do not
merge these separate concepts into a common abstraction merely because their structures resemble one another.

## Scope

- Inspect `Domain/Mcp/{Session,Phase,Observation,Activity,Detail,Usage,Notice,Subscription,Value}`, actual
  repositories/read contracts, Commands/Queries/events and consuming adapters/handlers.
- Keep Session, Phase, Observation and Notice responsibilities with their actual roots. Give missing aggregate
  identities meaningful value types, preserving project/session/producer/scope tuples and exact existing bytes.
  Existing ObservationId already extends ValueObject through UniqueId and is not a replacement target.
- Classify references/selections, occurrences, activity/usage measurements, capture metadata and Notice values.
  Every type classified as a value must extend ValueObject directly or through a meaningful value base and own
  stable reconstruction, same-type equality, hash and deliberate JSON semantics. Do not force native enums,
  Entities, query DTOs or repository interfaces into ValueObject.
- Remove `Domain/Mcp/Value/ObservationFields` as a catch-all static helper. Structural decoding belongs with its
  owning representation; shared name/reference validation belongs with genuine semantic values where justified.
  Do not recreate a generic Domain validator/service bucket or unify different reference grammars for convenience.
- Remove RecordedObservation's receipt-only wrapping where the recorded Observation itself suffices; if an
  operation receipt is genuinely needed, place it in Application Data. Preserve root-owned recording time and
  post-commit fact construction. Assess RecordedNotice separately: its commit-position semantics are substantive,
  not grounds for deletion by name similarity.
- Preserve bounds, supplied occurrence precision, missing/unknown/completeness meanings, protected-body separation,
  safe reference-only facts, relationship invariants and read-side selection/grant distinctions.
- Update callers, persistence/message codecs, tests, public/internal classification, execution/Notice guides,
  CONTEXT, examples and CHANGELOG. Retain actual domain services only for demonstrated domain knowledge.
- Out of scope: new aggregates for technical heartbeats/subscription registrations, changing database schema,
  domain vocabulary unification, workflow authority, automatic capture, retention policy or released primitives.

## Validation and permissions

Typed identities and values are not credentials. Preserve fresh recording/read/removal/recovery permissions,
concealed identities, activity-versus-protected-detail grants and sanitized failures. Do not broaden admitted
formats or silently normalize identifiers. Caller transactions and post-commit effects retain existing contracts.
