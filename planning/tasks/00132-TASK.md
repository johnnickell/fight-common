## Scope

- In scope: abstract Domain/Value/Internet/IpAddress and final immutable IpV4Address/IpV6Address with named string
  factories and existing Value/ValueObject equality, hash, string and JSON conventions.
- In scope: generic fromString family dispatch, strict family-specific parsing, deterministic canonical dotted-decimal
  IPv4/lowercase compressed IPv6, mapped-address family preservation and stable reconstruction.
- In scope: direct normal/failure/normalization and real hash-collection evidence; unchanged existing Validate and
  Application validation-rule behavior; public manifest/behavioral classification, docs/values.md and CONTEXT.md.
- Out of scope: DNS/network I/O, reachability/permission/SSRF policy, CIDR/subnets/routing, port or zone context,
  URI parsing changes, automatic migration of validation/adapter callers, Identifier or new sorting contracts,
  persistence types/schema/migrations, new helpers without an accepted need, new runtime dependencies and
  packaging/release-process tests.

## Validation and permissions

Factories accept bare literal strings without trimming or contextual interpretation. Reject empty/malformed values,
out-of-range IPv4 components, ambiguous leading-zero IPv4 forms, surrounding whitespace, hostnames, CIDR, bracketed
URI hosts, ports and zone identifiers. Family-specific parsing must not convert or accept the other family; an
IPv4-mapped IPv6 literal remains valid IPv6 and invalid IPv4. Do not infer a port from a final IPv6 hextet: a valid
bare IPv6 literal remains an address. Preserve the existing Validate/Application rule contracts rather than
redefining them as a side effect of adding new values.

Use stable dotted-decimal IPv4 and deterministic lowercase compressed IPv6 output. Equivalent zero-run/case forms
and dotted/hexadecimal mapped forms must produce the same retained representation, independent of input spelling.
Document the exact zero-run/mapped rendering policy and verify it rather than treating one native formatter probe
as a universal platform promise. Native parsing/rendering/storage mechanics remain routine implementation choices
within these approved guarantees, with no new external dependency or network call.

Use existing concrete-type ValueObject equality/hash/string/JSON contracts; mapped IPv6 and IPv4 stay different
values. The generic factory and each family factory must reconstruct their canonical output consistently with the
existing Value factory contract. No consumer extension, third-party address family or cross-family ordering promise
is inferred just from an abstract PHP declaration; deliberately classify intended operations under ADR 0009.

Invalid/wrong-family values raise DomainException. Valid syntax does not establish reachability, public routing,
trusted origin, permission or public-safe presentation. This is not a CIDR value or a sanitization/redaction boundary.
