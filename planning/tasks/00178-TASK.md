# Separate MCP metadata grammar machinery

## Outcome

Keep `McpRequestMetadata::fromObject()` and its immutable public context unchanged while giving independently
changing trace-context and implementation-icon grammars cohesive internal owners. This is a behavior-preserving
refactor, normally one PR, not a protocol correction or a public namespace move.

John approved planning this recommendation on 2026-11-02. The inspected source is develop `521a71c`; refresh source
and tagged-release facts before implementation. This record owns the accepted scope.
Planning approval is not implementation, publication or release authorization.

## Scope

- In scope: `src/Application/Mcp/McpRequestMetadata.php`, directly related internal grammar collaborators,
  focused metadata/decoder tests, explicit internal classification and affected descriptive documentation.
- Keep metadata construction/orchestration with its owner; extract coherent trace-context and implementation-icon
  machinery, including the URI/MIME/encoding rules that those grammars actually need. Select precise names from
  responsibility, not one class per predicate or a generic `ValidationHelper`.
- Preserve public namespace, constants, construction, accessors, accepted/rejected input and error contracts.
- Out of scope: new public validator interfaces, a generic grammar framework, tighter protocol acceptance,
  capability-interface redesign, HTTP/policy changes, schema/storage changes or dependency-floor changes.

## Validation and permissions

Preserve input byte/depth budgets, JSON object/list distinctions, exact defined-field rules, trace and baggage
syntax, URI/MIME/percent-encoding/Base64 edge cases, and current empty/open-object acceptance. Metadata is not a
credential, principal or authorization context. Consumers retain identity and business permissions; extraction
must not execute content or infer trust from a protocol value. No transaction or external delivery is introduced.
