# Construct Strict Zoned DateTimes

## Outcome

Consumers construct a zoned value without silently normalizing DST gaps or choosing an overlap occurrence, and
preserve exact instants through native/serialized round trips. Deliver immutable DateTime, strict local/native
construction, owned equality/comparison/conversion and complete evidence/docs in one independently reviewable PR
under [TICKET-00036](../tickets/00036-TICKET.md) and [EPIC-00008](../epics/00008-EPIC.md).

## Validation and permissions

Local construction must receive an explicit Timezone and valid Date/Time; the supported local calendar range is
TASK-00134's years 0001–9999 with exact microseconds. Reject unsupported value/conversion ranges predictably rather
than truncate/normalize or require a new 64-bit installation. In particular, an instant-preserving conversion whose
target local date is outside the supported Date range fails rather than silently changing the instant.

Reject nonexistent local times even when an offset is supplied. If a local time has multiple real occurrences,
require a supplied offset in integer seconds and validate that it selects an occurrence. If an offset is supplied
for an ordinary unique local time, it must also agree with the timezone. Do not assume a one-hour shift, whole-minute
historical offsets or an available transition table for every accepted timezone: fixed-offset and abbreviation
contexts accepted by existing Timezone remain supported without narrowing Timezone itself.

DateTime identity is exact instant plus DateTimeZone::getName()-style native identifier. Preserve distinct IANA
aliases and native identifier spelling; native normalization of offset spelling makes +5:30 and +05:30 share the
native identifier +05:30. This rule belongs to the new DateTime, not a changed Timezone equality/canonicalization
contract. Native import/export and canonical reconstruction must preserve that identity and microseconds.

Value ordering compares instants first, native identifier second, returning -1/0/1 and zero exactly for equal
DateTime values. Expose separate isSameInstantAs (provisional spelling) and an owner-defined instant-comparison
mechanism usable by intervals; interval semantics must not inherit the identifier tie-breaker. Wrong-type equality
is false; invalid construction/reconstruction/conversion and wrong-type value comparison use DomainException.
Document native/type-boundary failures and causal behavior under ADR 0011 rather than fabricating universal handling.

Capture immutable native state/scalars rather than retain caller-owned mutable DateTime. Serialized identity must
retain exact instant coordinates and native identifier, not only wall components or a minute-only offset. Preserve
pre-epoch seconds/fractions without interpreting native U.u text as an ordinary signed decimal or using floats.
Do not aggregate all supported dates into integer total microseconds if that narrows native representability.
Final factory names, codec grammar and storage mechanics remain routine design within these guarantees.

Reconstruction of a saved instant is not fresh ambiguous local construction: it already identifies an occurrence.
Validate the supported representation, and any explicitly encoded local/offset data for coherence, without losing
that instant. Timezone rules come from the runtime; no frozen tzdb guarantee is added. Rule changes must not turn
saved instant identity into silently reinterpreted wall-clock identity. Distinguish instant-preserving conversion
from local reinterpretation in API names/docs, applying strict invariants to the latter.
