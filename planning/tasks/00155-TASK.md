# Inspect execution summaries and activity through MCP

## Outcome

Authorized MCP callers can inspect full-selection statistics, execution pages, selected execution summaries/phases
and phase activity through explicitly registered read-only Tools. Deliver the complete guarded HTTP → Tool → shared
Query → DBAL path as the first approved vertical slice of [TICKET-00043](../tickets/00043-TICKET.md).

John approved two TASKs: safe inspection, then separately protected-detail inspection. TASK-00151 and TASK-00152
supply the shared safe Queries; their dependencies transitively supply TASK-00150's summaries/pages and recording.
Reuse `QueryBus::fetch()`, current application access enforcement and the existing guarded HTTP/Tool contracts.
Qualify the journey with the existing SQLite, MySQL and PostgreSQL adapters. No global execution priority is assigned.

- In scope: opt-in safe inspection Tools, argument/output schemas, safe projection, trusted-context composition,

Map only declared selection/reference fields into the shared use cases. Consumer composition supplies trusted
scope/access context; Tool arguments and protocol/envelope metadata are not authority. Neither adapter projection
nor a response transformer may calculate a competing aggregate, decide business permission or fetch missing
business data directly. Use typed safe results, preserving all-authorized-match summaries rather than page totals,
units/provenance, known versus unknown/partial/unmeasured values and actual persisted-evidence freshness.

Preserve live `page`/`per_page` semantics and the accepted immutable recording-time/full observation UUID order.
Keep occurrence time/source precision distinct, performing Agent/model/producer distinct, and observed outcome
separate from Workflow truth or independent acceptance. MCP catalog pagination remains a separate existing protocol
contract; it grants no data access or stable cross-request application result.

Establish bounded MCP presentation for reuse by TASK-00156. Existing schema validation and `McpToolOutput` JSON
safety are not a final encoded-response byte guarantee. Enforce finite application/projection bounds and qualify
final encoded responses including structured content, its compatible text companion, escaping and protocol overhead
(including applicable response identity/metadata). Reject oversized output safely before disclosure rather than
silently truncating statistics or history. Preserve existing runtime schema validation and central responder/error
contracts; choose a compatible bounded implementation rather than another endpoint or general CQRS bridge.

## Validation and permissions

Check current Tool availability independently of the shared use case's current access decisions. Discovery,
endpoint access, pagination values and detail references grant no business access. Validate supported selection
fields, identifiers, relationship scope, types and finite bounds; runtime schema validation supplements rather
than replaces application validation. Recheck availability/access on later calls, including revocation between
listing and invocation. Human permissions never implicitly authorize Agents.

Safe summary/activity outputs, text companions, discovery and public errors contain no protected bodies or concealed
metadata. Unexpected storage/application errors use existing safe failure/diagnostic conventions, never exception
messages or credentials. Inspection dispatches no mutation Commands or domain events; test seeding remains a
separate trusted application operation. Structural separation does not become universal capture redaction.
