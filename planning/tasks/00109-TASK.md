# Deliver Fight Common progressive MCP HTTP and SSE adapters

## Outcome

Deliver and prove Fight Common's HTTP/SSE side of progressive Tool calls. The package selects direct JSON or
request-scoped SSE, serializes TASK-00108 progress and final representations, exposes a concrete live-emission
capability, translates it through supported package adapters where appropriate, and propagates observed client
closure as cooperative cancellation. Starter-owned routes and booted installed-package qualification remain in
[TASK-00110](00110-TASK.md).

## Scope

- In scope:
  - HTTP extraction of already decoded MCP request metadata and direct-JSON versus progressive-SSE response-mode
    selection over TASK-00105's guarded endpoint.
  - Exact SSE serialization for request-related `notifications/progress` messages followed by the final JSON-RPC
    response, including `text/event-stream`, no-cache behavior, `X-Accel-Buffering: no`, prompt flush boundaries,
    termination after the final response, and no non-MCP event or sentinel leakage.
  - A named framework-free concrete emitter/runtime composition owned by the package because PSR-7 does not
    standardize live emission, buffering control, or disconnect callbacks. Prove it with PHP's built-in server and
    a no-buffer client or an equally explicit executable package harness.
  - The smallest shared capability-scoped emitter boundary needed by the package, plus Symfony and Laravel native
    response translations and Yii, CodeIgniter, and Slim package translations only where conformance evidence
    demonstrates a missing boundary under ADRs 0021 and 0024.
  - Closure observation that marks TASK-00108's request cancelled and suppresses all later progress/final bytes.
  - Shared package conformance fixtures for framework-free/PSR, Symfony, Laravel, Yii, CodeIgniter, and Slim
    adapter compositions, including success, failures after progress, direct JSON, buffering, and disconnect.
  - Additive compatibility-manifest classification, `CONTEXT.md`, and consumer-facing composition/operations
    documentation for package-owned additions.
- Out of scope:
  - Changes to the Symfony, Laravel, Yii, CodeIgniter, or Slim starter repositories, including their routes,
    framework configuration, runtime/server wiring, candidate dependency installation, or support receipts.
  - Claiming framework support from package tests alone. Booted installed-package journeys are owned by
    [TASK-00110](00110-TASK.md) and the corresponding starter repositories.
  - Consumer authentication, authorization, principals, Origin policy, gateway, worker, proxy, or deployment
    policy beyond documenting the conditions used in package evidence.
  - Long-lived subscriptions, resumable streams, durable Tasks, partial Tool-result streaming, forced interruption,
    transaction rollback, legacy HTTP+SSE/session support, or a buffered/preassembled SSE imitation.

## Use cases and contracts

| Use case | Actor and trigger | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|---|
| Select direct JSON | Guarded HTTP request contains no progress token | The one Tool-owned Command, if selected | The one Tool-owned Query, if selected | N/A | Use TASK-00108's no-op reporter and return the ordinary complete JSON response without entering streaming mode. |
| Select progressive SSE | Guarded HTTP request contains a valid progress token | The one Tool-owned Command, if selected | The one Tool-owned Query, if selected | N/A - MCP protocol notifications are not Fight Events | Return the progressive response, expose each serialized `notifications/progress` message before the final JSON-RPC response, and terminate. |
| Translate a package adapter | Consumer composes a documented Common HTTP adapter or framework-native response translation | N/A beyond selected Tool behavior | N/A beyond selected Tool behavior | N/A | Preserve the shared producer's exact headers, framing, flush, finalization, and cancellation behavior without taking route ownership. |
| Fail after progress | Tool execution, conformance, or response preparation fails while the stream remains open | No additional Command | No diagnostic Query | N/A | Serialize exactly the TASK-00108 final error representation, expose it once, then terminate; no internal detail or success reinterpretation leaks. |
| Disconnect an open stream | Concrete emitter observes that the client has closed this request | No new Command | No new Query | N/A | Mark only this request cancelled, stop writing, and expose no later progress, error, or final bytes. |

## Validation and permissions

TASK-00105 and TASK-00108 remain authoritative for guarded HTTP validation, Origin/invocation guards, progress-token
semantics, Tool availability, reporter state, and semantic failure classification. This TASK may translate decoded
metadata and semantic representations into HTTP delivery; it must not reinterpret a Tool result, bypass validation,
or introduce framework-specific permission behavior.

PSR-7 standardizes message and stream interfaces, not when bytes become client-visible or how disconnect is
observed. The framework-free claim therefore requires an explicit executable emitter/runtime, planned as a
package-owned fixture under PHP's built-in server with a no-buffer client unless implementation evidence justifies
an equally concrete substitute. A callback invocation, in-memory body, or mocked disconnect flag is insufficient.

Symfony and Laravel native streaming APIs are candidate translations, not support proof by inspection. Laravel's
default event name or terminal sentinel must not leak if it contradicts MCP framing. CodeIgniter's stored-string
response, Slim's ordinary chunk loop without proven flush behavior, and Yii's complete-body PSR path are also not
accepted as live emission. Add only the narrow shared/package adapter established by evidence. If any package
composition cannot express the full contract, stop with its exact limitation rather than widening a public surface
speculatively or downgrading acceptance.

Routes, authentication, principals, and authorization remain consumer-owned. Package adapters receive no Agent,
credential, permission, raw Tool arguments, or authorization decision beyond TASK-00105's accepted request
boundary. Connection/runtime errors after closure remain server-side.

## Acceptance criteria

- [ ] A request without a progress token uses the no-op reporter and returns TASK-00105's unchanged direct JSON;
  a valid token selects the progressive HTTP path exactly once.
- [ ] The framework-free path names a concrete emitter/runtime and proves with a live server/client harness that at
  least two progress events cross client read boundaries before the final response; a PSR-7 body alone is rejected.
- [ ] Every progressive response uses valid `text/event-stream` framing, no-cache behavior and
  `X-Accel-Buffering: no`; notifications precede the final JSON-RPC response, which terminates the request without
  a session, resumability, framework sentinel, or non-MCP event-name claim.
- [ ] Shared conformance fixtures exercise package-level framework-free/PSR, Symfony, Laravel, Yii, CodeIgniter,
  and Slim translations while preserving optional dependency boundaries and consumer-owned composition roots.
- [ ] Each package composition proves success and no-token direct JSON, plus an expected Tool error after progress,
  an unexpected `Throwable` after progress with once-only diagnostic and sanitized final error, and early
  disconnect with no later bytes.
- [ ] Closing a supported response marks only that request's reporter cancelled. Evidence distinguishes cooperative
  early stop from already-dispatched work and makes no rollback guarantee.
- [ ] No package test, adapter inspection, or mocked emitter is described as a booted installed-package starter
  journey; TICKET acceptance remains incomplete until TASK-00110 records all five starter receipts.
- [ ] A public adapter is added only for an evidenced missing translation boundary and is limited to that
  capability under ADRs 0021 and 0024; existing JSend and unrelated framework registrations remain unchanged.
- [ ] Every public addition is manifest-classified, promised operations are explicit, and `CONTEXT.md` plus package
  documentation identify exact tested emitter, SAPI/server, buffering, disconnect, and consumer-wiring conditions.

## Verification and evidence

Build a shared progress-stream conformance suite and run it through the framework-free/PSR baseline and each
package adapter/translation. Pair focused unit/contract tests for metadata extraction, mode selection, SSE encoding,
headers, adapter translation, completion, error finalization, and closure propagation with a live PHP built-in
server and no-buffer client/process or socket harness. For every package composition, capture a matrix covering
multi-event success, expected Tool failure after progress, unexpected failure after progress, no-token direct JSON,
and early disconnect. Record event read boundaries or timestamps, the actual SAPI/server, response/emitter,
output-buffer settings, diagnostic count, and absence of bytes after closure.

This is a library/API integration change with no useful visual UI. Before evidence is the current complete-body
JSend/PSR response behavior and TASK-00108's controlled semantic transcript. After evidence is the package
conformance and sanitized wire/timing matrix; it is not starter support evidence. Save complete logs, transcripts,
environment matrix, and canonical `./bin/build` log/exit receipt under the TASK's ignored run directory. Run
`./bin/build` before publication and surface warnings, buffering dependencies, flaky timing, unsupported runtime
behavior, or incomplete compatibility evidence.
