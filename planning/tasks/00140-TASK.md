# Define 49 Common Currency Values

## Outcome

Consumers construct immutable Currency values for a deliberately bounded set of 49 commonly used currencies,
with package-owned accounting scales and stable code identity. Deliver the usable Currency/definition boundary,
direct tests and documentation in one PR under [TICKET-00037](../tickets/00037-TICKET.md) and
[EPIC-00008](../epics/00008-EPIC.md). [TASK-00141](00141-TASK.md) consumes it to deliver Money.

John approved the original feature TASK on 2026-10-06. On 2026-10-09 he replaced the proposed broad catalog with
38 selected trade-observed currency codes (excluding BGN) plus 11 curated additions, a **49-code** set. The
previous data-reuse blocker no longer applies: this TASK does not vendor or maintain a published currency table.
The set is a product choice, not a global usage ranking or a claim of complete currency coverage. There is no
TASK blocker or execution priority; additive next-minor delivery still requires compatibility assessment and
separately authorized implementation.

## Scope

- In scope: final immutable `Domain/Value/Money/Currency`, named code construction, canonical uppercase code
  identity, string/JSON reconstruction and an immutable package-owned code/scale definition for each of the
  selected 49 codes.
- In scope: current recognized codes, supported base-ten accounting exponents 0/2/3, stable definition identity
  for saved Money reconstruction, controlled future additions/retained-reader behavior, malformed/unknown rejection,
  direct value tests, public classification, docs/values.md and CONTEXT.md.
- Out of scope: a complete worldwide or historical catalog, numeric codes, display names, country rows, exchange
  rates, withdrawal/legal-tender claims, external-source tables or documents, online/clock lookup, cash rounding,
  automatic successor conversion, arbitrary consumer-invented scale, schema/mappings, new dependencies and
  release-process tests. Support for other currencies is later additive work, not a runtime guess.

### Exact supported set

| Accounting exponent | Codes |
|---|---|
| 0 | CLP, JPY, KRW, VND |
| 3 | BHD, KWD |
| 2 | AED, ARS, AUD, BDT, BRL, CAD, CHF, CNY, COP, CZK, DKK, EGP, EUR, GBP, HKD, HUF, IDR, ILS, INR, KES, LKR, MAD, MXN, MYR, NGN, NOK, NZD, PEN, PHP, PKR, PLN, QAR, RON, RUB, SAR, SEK, SGD, THB, TRY, TWD, UAH, USD, ZAR |

The table defines **49 distinct codes** (4 + 2 + 43). It is not a rank order. Accounting exponent is not a
promise about physical denominations, cash rounding or whether a consumer may transact in a currency.

## Validation and permissions

Only listed uppercase ASCII codes are accepted; lowercase, malformed and unsupported codes reject rather than
normalizing or inventing Currency instances. Currency identity/hash uses the code alone. Each immutable definition
has an accounting exponent and stable version/identity available to Money. Metadata/output must not expose mutable
shared state. Future additions are compatible when documented; changing a supported definition must not silently
reinterpret old Money, drop old supported reads or redenominate. Do not infer precision from a code's spelling or
external runtime state. No public dynamic catalog-registration framework is required.
