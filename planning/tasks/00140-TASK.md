## Validation and permissions

Canonical identity is the recognized uppercase ASCII alphabetic code. Use Value/ValueObject conventions with code-only
identity/hash; numeric code, display name, source revision and current/historical metadata do not participate in
identity. Preserve numeric metadata as three-character strings, including leading zeros, rather than ints or
historically unique lookup keys. Document supported factory spellings; reject unknown/malformed code values with
DomainException, not a fallback currency or dynamically invented enum member.

Construction performs no network lookup or runtime XML synchronization. Use immutable selected-snapshot definitions;
existing values must not change as callers read metadata or mutate returned data. Publish source/version/provenance
and distinguish current status from historical records. An entry in List Three is not sufficient to mark a code
withdrawn globally when it also exists in List One. Historical withdrawal/name/country observations are not universal
legal-tender periods or a complete economic-transition chronology. Do not use the ambient clock or temporal TASKs
as a dependency to reinterpret a pinned catalog's status.

ISO accounting fraction digits, physical subdivisions and consumer cash-rounding rules are separate. Preserve zero
as a valid exponent and ISO N.A. as unavailable. Historical precision requires primary evidence or explicitly scoped
and justified legacy evidence, not copied Novuso defaults or arbitrary two digits. Conflicting/ambiguous definitions
must not silently choose a scale. Currency remains representable when precision is unavailable; minor-unit Money
requires a supported definition. Audit the complete selected historical inputs, not just the twelve sampled withdrawals.

Retain supported precision definitions and recognized historical codes needed for future saved-Money reads. Metadata
maintenance cannot silently mutate a definition's meaning, drop old supported reads, change saved scale or replace
withdrawn codes. Final catalog/definition APIs, storage mechanics and maintenance documentation remain routine design
within these guarantees; no public extensible catalog framework or arbitrary consumer-minted ISO precision is required.
