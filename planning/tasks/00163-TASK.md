### Approved inspection mechanics

Read TASK-00162's technical DBAL registrations directly on SQLite/MySQL/PostgreSQL through inward-owned contracts.
No duplicate lifecycle store or asynchronous projection is required. Consumer interfaces use the same Queries,
not adapter SQL or alternate authorization/aggregate logic. Define the deployment/registration scope observed by the
store: process-local visibility cannot be presented as the entire installation. Present observation time/freshness
and availability honestly rather than calling a recent heartbeat proof that the client is still connected.

Distinguish requested filters from the subset accepted at opening. Represent permitted topic/Resource references
without implying that acknowledgment grants continuing access. Count subscriptions distinctly from subscriber
identities: one identity may have multiple simultaneous streams, and JSON-RPC IDs are not globally unique. Filter/
reference joins must not multiply totals. Unknown identity/context remains explicit; do not infer receipt, processing
or historical audience from active matches or an intended-recipient reference.

Summaries cover all currently authorized matches, not the current page or a concealed global selection. Bound
returned dimensions and fields without materializing the whole registration set or silently truncating full-selection
meaning. Use stateless live `page`/`per_page` pagination with `Pagination::strict()`, explicit selection/order allowlists,
finite request/page/result limits and deterministic ties. Strict construction does not authorize arbitrary fields or
SQL. Document supported filters, count units, defaults and consistency between summary/pages; rows/totals may change,
repeat or be skipped between calls. No remembered browsing, UI page-reset behavior or snapshot across requests.

Reuse TASK-00162's qualified ownership/freshness/closure semantics. Show recently observed, disconnected or stale/
uncertain state as supported by actual evidence. An expired heartbeat is not proof of a clean disconnect; a missing/
cleaned row is not proof that no subscription existed. Inspection must not renew liveness or clean rows as a read side
effect. Bound lifecycle retention/cleanup under its existing owner rather than adding a historical subscriber archive.

## Validation and permissions

Consumers supply current independent subscriber-inspection decisions. Permission to listen, read notices or inspect
one's own stream does not imply global operator access. A SUPER_ADMIN label, caller-provided identity/scope, protocol
request ID or prior page grants nothing; human access does not imply Agent access. Apply current authority to every
summary/page and each identity/filter/reference field, including totals and freshness metadata. Do not globally
aggregate then merely filter rows afterward.

Validate finite selection/time/state/reference inputs where supported, allowed order fields/directions, positive
representable page bounds and encoded result limits. Define safe unknown/denied behavior and diagnostics without
exposing concealed registrations, filter requests, credentials or protected bodies. Storage failure is explicit,
not empty success or confidently disconnected state. No business Commands/events or new consumer permission model.
