# Apply activity visibility consistently to execution summaries

## Outcome

Hidden activities cannot affect statistics or other activity-derived inspection fields disclosed to a caller.
Apply current activity visibility consistently to browsing and execution inspection. This is a bounded security
repair proposed for the 1.5 maintenance line and a separately authorized v1.5.1 patch release.

John approved the proposed scope and explicitly required branching from `1.5`, not `develop`. This approval
accepts the scope and record creation; it is not implementation acceptance, publication or release approval.
The reported consumer TASK-00089 remains a separate consumer-owned record, not Common's unrelated archived
TASK-00089.

## Scope

- In scope: apply current activity restrictions before aggregate activity counting and exact usage calculation;
  inspect and correct related activity-derived freshness/model projections; align permission documentation,
  CONTEXT.md and affected release notes with the corrected behavior.
- Preserve existing unrestricted callers, session/phase state semantics, finite full-selection reads and independent
  reference/body permissions. Explicitly account for the change to the released permission contract: current docs
  say activity grants restrict browsing only while aggregates retain session/phase scope.
- Out of scope: consumer policy/composition changes, consumer TASK-00089 implementation/resumption, capture,
  schema redesign, new permission framework, release certification/signing/publication, or speculative older-line
  backports. Inspect older-line applicability before proposing any separate backport.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Caller browses one of two retained activities and inspects statistics | N/A: read-only | ListPhaseActivity; SummarizeExecutions; GetExecution | None | Count and usage include only currently permitted activity |
| Caller inspects related execution/phase projections | N/A: read-only | ListExecutions; ListExecutionPhases; selected execution inspection | None | Hidden activity cannot influence disclosed activity-derived freshness/model fields |
| Caller loses activity access or requests another page | N/A: read-only | Repeat affected Queries with fresh admission | None | Current full-selection permitted results, not cached grants or page-local totals |
| Caller supplies invalid or concealed scope, or storage fails | N/A: read-only | Existing affected Queries | None | Preserve safe validation/absence/denial and explicit failure, without business writes |

## Validation and permissions

Preserve project/session/phase intersection and producer/full-UUID activity identity constraints. Apply activity
restrictions before loading/aggregating concealed activity, not by filtering a completed global summary. Reference
metadata and protected-body permissions remain independent and cannot be inferred from aggregate or row access.
Omitted/null activity restrictions retain existing unrestricted semantics; explicit empty grants conceal activity.
Reject invalid inputs safely; do not disclose private causes, concealed totals or usage. Storage/corrupt-evidence
failures must not become successful empty/partial results. Separate live calls remain non-snapshot reads; this
repair does not promise frozen results or infer Workflow completion from activity.

## Acceptance criteria

- [x] With unchanged data and the same current grants, one permitted activity of two yields list total 1, summary
  activity count 1 and only the permitted activity's usage, including selected-execution statistics.
- [x] Explicit empty activity grants yield activity count 0 and no activity-derived usage while retaining separately
  authorized session/phase evidence and existing missing-usage semantics.
- [x] Hidden activity cannot change disclosed derived freshness, ordering or model projections; independently
  permitted state/detail evidence retains its existing separately authorized meaning.
- [x] Unrestricted callers retain existing counts, exact usage, bounds and safe results; pagination does not narrow
  full-selection statistics. Producer/full-UUID identities and project/session/phase isolation remain correct.
- [x] Fresh admission, revocation between calls, reference/body separation, safe invalid/missing/denied behavior and
  explicit storage failures remain intact, with no business writes/events.
- [x] Documentation and release notes explicitly describe the corrected visibility contract and patch impact.
