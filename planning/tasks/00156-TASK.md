# Inspect separately protected execution detail through MCP

## Outcome

An MCP caller with separate current protected-detail permission can inspect bounded captured messages, linked tool
arguments/results and process-output chunks. Deliver explicitly registered protected-detail Tools through the
existing guarded HTTP composition and shared Queries, completing the summary → execution → phase/activity → detail
journey of [TICKET-00043](../tickets/00043-TICKET.md) and [EPIC-00009](../epics/00009-EPIC.md).

TASK-00155 supplies safe inspection and bounded MCP presentation; TASK-00153 supplies protected Queries and their
storage dependencies. Reuse both without a second capture/store/query subsystem or permission policy. Qualify the
journey with the existing SQLite, MySQL and PostgreSQL adapters. No global execution priority is assigned.

## Scope

- In scope: opt-in protected-detail Tools, validated arguments/output, fresh separate permission on every page/chunk,
  typed content projection, finite encoded bounds and complete application/MCP journey evidence.
- In scope: truthful content types, chunk boundaries, capture completeness/absence, revocation and disappearing
  content, safe errors, compatibility, docs/CONTEXT.md, exact coverage and full local verification.
- Out of scope: recording/removal/status mutation Tools, public removal implementation, retention orchestration,
  direct database access from Tools, automatic capture/redaction, hidden reasoning or complete-capture guarantees.
- No new endpoint, principal model, generic CQRS bridge, UI or Prompts/Subscriptions/asynchronous Tasks dependency.

Use TASK-00155's existing HTTP/Tool composition and bounded presentation. Map only declared arguments into
TASK-00153's Queries and supply trusted caller/scope decisions through consumer composition. Do not infer authority
from `_meta`, a scope/reference argument, available Tool, listed execution or prior successful read. No Resource
capability or automatic URI/file/network access is needed to present the captured detail.

Preserve content types and valid text/byte representation under the shared contract, including empty bodies,
partial capture and bounded continuation. Reaching the end of retained bytes does not prove the original output
was fully captured. Supplied expired markers remain distinct from unknown absence; a missing row alone cannot
establish expiry or reconstruct unobserved content. Safe activity must not advertise missing detail as available.

Each collection page/chunk is a new authorized request with live semantics, not a frozen result or retained-content
lease. Carry through the accepted recording-time/full UUID ordering and honest source precision for observation
collections. Changes may repeat/skip rows or remove content between calls. Document the inherited continuation and
race behavior rather than promising cross-request stability or retraction of already disclosed bytes.

Apply finite limits to the full encoded result, not only raw body bytes or structured schema values. Reuse
TASK-00155's accounting for structured content, matching text, escaping and protocol overhead/applicable metadata.
Test large, multi-byte and escape-heavy content. A valid application result can still exceed the protocol budget;
fail safely before disclosure, without silent data loss, successful-empty substitution or fabricated completeness.

## Validation and permissions

Current Tool availability and separate current detail permission are independent checks on every page/chunk.
Human permission, timeline access, previous requests, references and endpoint admission do not authorize an Agent's
body retrieval. Validate supported argument fields, finite pagination/chunk bounds and scope/session/phase/detail
relationships through the existing runtime schema path and shared use cases. Unknown/denied identities and
cross-project references must not expose concealed metadata or content through any protocol representation.

Protected content appears only in successful separately authorized detail results. Keep safe summary/activity
Tools, discovery, public errors and diagnostics free of unauthorized content. Reuse fixed safe failures and
consumer redaction-aware diagnostics; raw storage exceptions and credentials are never response text. Reads issue
no mutation Commands or domain events. Consumers retain identity/policy, capture selection and redaction ownership.
