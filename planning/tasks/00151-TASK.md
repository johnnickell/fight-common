# Inspect an execution summary and its phases

## Outcome

A human or authorized Agent can select an execution and inspect its safe summary and bounded phase pages through
shared application Queries. Deliver the typed results, current authorization, handlers and direct DBAL reads as
the second approved vertical slice of [TICKET-00041](../tickets/00041-TICKET.md).

[TASK-00150](00150-TASK.md) supplies the shared read contracts and authorization implementation, with admitted
session/phase/activity/usage records supplied transitively by TASK-00147/00148. Initial direct reads are qualified
on SQLite, MySQL and PostgreSQL; no asynchronous projection or Event Store dependency is introduced. No global
execution priority is assigned. This TASK does not depend on TASK-00152's activity browsing.

## Scope

- In scope: selected-execution summary and paginated phase Queries, safe phase parent/session relationships,
  attempts, performing Agent identity, observed timing/outcome and measured usage with units/provenance.
- In scope: fresh read admission, finite response/page limits, strict supported filter/order validation, actual
  DBAL reads, compatibility, documentation and complete local verification.
- Out of scope: a second overview implementation, phase activity/detail references (TASK-00152), protected bodies
  and removal (TICKET-00042), MCP, UI navigation, Workflow/review acceptance, retention and frozen browsing.

## Use cases and contracts

Operation labels are responsibilities, not final PHP names.

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Caller selects a permitted execution | N/A; read only | Inspect execution summary through `QueryBus::fetch()` | N/A | Return safe observed timing/outcome/usage and explicit freshness |
| Caller browses the selected execution's phases | N/A; read only | List execution phases | N/A | Return bounded live phase pages with authorized metadata and relationships |
| Caller supplies a guessed ID or access changes | N/A; read only | Repeat summary/phase Query with fresh admission | N/A | Safe denial/absence according to the documented Query contract |
| New evidence arrives between summary and phase reads | N/A; read only | Independently requested Queries | N/A | Return each call's actual evidence without a shared frozen-result promise |

Reuse TASK-00150's read admission/selection/results and aggregation semantics rather than reconstructing permission
or measurement policy in the adapter. Phase collections use strict `page`/`per_page`, supported fields and documented
finite bounds. Explicitly define each Query's selection and ordering basis; preserve the accepted recording-time/
full observation UUID tie-breaker when selecting or ordering observation evidence, not an invented causal sequence.
Safe parent references are subject to access checks as well as relationship consistency.

Observed outcomes are evidence, not consumer Workflow state. A phase named review, successful surrounding execution
or process exit cannot establish an independent acceptance verdict. Preserve performing Agent identity separately
from model and instrumentation producer. Missing completion stays unknown; measurement absence is not zero, and
incompatible units/provenance must not be flattened into misleading totals. Summary calculations cannot be limited
to the current phase page or multiplied by related activity joins.

## Validation and permissions

Apply current consumer-supplied permissions to the selected execution, phase rows, summaries and exposed references.
Previous overview membership grants no access. Validate scope/execution/phase relationships, bounds and supported
filter/order fields, with safe behavior for missing, mismatched and concealed identities. Human permission never
implicitly grants Agent access. Keep protected bodies out of results and public failures; this TASK does not need
protected-content retrieval. Storage failure is not an empty successful response.

## Acceptance criteria

- [x] Real persisted execution-to-phase navigation works through shared Queries and actual DBAL reads on SQLite,
  MySQL and PostgreSQL, including more than one phase page and parent/attempt relationships.
- [x] Selected summaries reflect all authorized matching evidence, not only visible phase-page rows; units,
  provenance, unknown outcomes, missing/partial measurements and freshness are preserved truthfully.
- [x] Guessed IDs, cross-project or mismatched relationships, differing caller permissions and access revocation
  between calls are handled safely without hidden metadata, protected-body or total-count disclosure.
- [x] Invalid pagination, unsupported fields and finite response bounds reject clearly; empty phases, missing
  records and storage failures have documented, distinct safe behavior where disclosure is permitted.
- [x] Performing Agent/model/producer distinctions survive retrieval. Review labels and surrounding success are
  never inferred to confer acceptance or terminal Workflow state.
- [x] Ordering and live-page changes match the accepted contract, including tied recorded timestamps and full UUID
  comparison. Separate summary/phase calls do not claim unchanged data or a retained browsing session.
- [x] Reads issue no business mutations or domain events; existing recording/read contracts remain supported, public
  additions and schema/index changes are classified, and documentation/CONTEXT.md explain the behavior and limits.
- [x] Relevant tests, exact owned-code coverage and the complete local `./bin/build` gate pass with retained evidence.
