# Summarize and browse authorized executions

## Outcome

Humans and authorized Agents can fetch full-selection execution statistics and bounded execution pages through
shared Domain Query payloads handled by Application coordinators, with current access enforced consistently for
aggregates and rows. Deliver the typed
selection/results, read authorization, handlers and actual DBAL queries together as the first vertical slice of
[TICKET-00041](../tickets/00041-TICKET.md) under [EPIC-00009](../epics/00009-EPIC.md).

John approved three vertical TASKs and initial direct reads from the observation DBAL storage, qualified on SQLite,
MySQL and PostgreSQL. No asynchronous projection or Event Store dependency is introduced. TASK-00148 supplies
activity/usage and transitively TASK-00147's session/phase recording. No global execution priority is assigned.

## Scope

- In scope: full-selection counts, known outcomes, measured usage and explicit freshness; a bounded execution list
  using the same authorized selection semantics, not statistics calculated from the current page.
- In scope: reusable current-read admission, validated selections/filter/order fields, typed safe results, finite
  page/response bounds, DBAL aggregate/list implementation, compatibility, documentation and behavior evidence.
- Out of scope: selected execution/phase Queries (TASK-00151), phase activity/references (TASK-00152), protected-body
  reads/removal (TICKET-00042), MCP, UI, browsing sessions, retention policy, Workflow authority and new projections.

## Use cases and contracts

Operation labels describe responsibilities; exact PHP names, supported filter fields and finite limits belong to
implementation within these approved guarantees and must be documented.

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Caller requests an overview of its permitted selection | N/A; read only | Summarize matching executions through `QueryBus::fetch()` | N/A; reads are not domain changes | Return authorized full-selection statistics and freshness without mutation |
| Caller browses the same independently supplied selection | N/A; read only | List executions | N/A | Return a bounded live page and permitted total metadata |
| Data or access changes before the next request | N/A; read only | Repeat either Query with current selection/access | N/A | Reevaluate current access and stored evidence; no remembered browsing state |
| Caller submits unsupported fields or invalid bounds | N/A; read only | Same Query boundary | N/A | Reject safely without SQL-field injection or concealed-data disclosure |

Preserve `QueryBus::fetch()` and existing messaging contracts. Shared Queries are the sole application use cases
for future MCP and dashboard consumers; neither adapter owns competing policy or direct database access. Establish
read contracts reused by TASK-00151 and TASK-00152 as part of this working outcome, not an interface-only prefactor.

Use `Pagination::strict()` for page/per-page semantics, plus use-case field allowlists and finite bounds; strict
construction alone does not authorize fields or queries. Each request supplies its own selection. Totals and rows
may change, and inserts/removals can repeat or skip rows across pages. Separate calls are not a frozen result.
Document the actual consistency of reads within one response without promising a cross-request snapshot.

Aggregate executions rather than counting every observation as another execution. Related phase/activity joins
and deduplicated submissions must not multiply executions or measured usage. Explain how supported recorded
outcomes/measurements contribute; absent completion cannot imply success, and incompatible units cannot be summed.
Preserve provenance and explicit missing/partial/unavailable information. Bound aggregate output without silently
truncating the selection or materializing an unbounded execution result merely to calculate statistics.

Freshness describes the persisted evidence actually read, not complete producer capture or authoritative Workflow
state. Direct reads do not justify claiming a global latest-observation checkpoint or complete external history.
Apply the accepted recording-time descending/full observation UUID COMB descending default where ordering
observations determines the result, with the execution-list ordering basis explicit and deterministic.

## Validation and permissions

Consumer composition supplies trusted current caller scope/access decisions, including human/Agent differences.
Enforce them before both aggregation and row selection; post-filtering a global total is not authorization. A scope
ID, previous page or earlier success is not a grant. Validate finite selections, supported filter/order fields,
pagination and relationships. Reject guessed or out-of-scope inputs without disclosing concealed records.

Return only safe observation data; protected messages, tool arguments/results and process output are excluded from
results, filters over bodies and public errors. Do not introduce authentication, a role hierarchy, automatic secret
detection or permission inference from instrumentation identity. Storage failure must not become a successful empty
selection. Queries perform no business writes or domain-event dispatch.

- [x] Documentation and CONTEXT.md cover selections, limits, aggregation, permissions, ordering, freshness, direct
  DBAL composition and live pagination. Relevant tests, exact owned-code coverage and full `./bin/build` pass.
