# Contain terminal Laravel safe-error rendering faults

## Outcome

Selected safe Laravel JSON handling returns a fixed generic native response even when primary and fallback JSON
encoding fail, without escaped rendering diagnostics or recursive reporting. One bounded patch TASK normally owns
one PR. John approved this scope, record creation and the proposed `1.4` patch base in the intake conversation;
the implementation checkout choice is **isolated worktree**. The implementation on the approved 1.4 patch base has independent Review acceptance and behavioral QA PASS at the accepted candidate recorded below.

This is high-priority, security-relevant supplier repair blocking AccessControl TASK-00105. No numeric Board
priority is assigned. That downstream TASK is not a Common dependency or a parent TICKET.

## Scope

In scope:

- `src/Adapter/Http/Laravel/SafeLaravelExceptionHandler.php`: contain terminal rendering faults on the selected
  JSON path, including fallback reached after a failed diagnostic sink or projector.
- Mirrored runtime regressions in `tests/Adapter/Http/Laravel/SafeLaravelExceptionHandlerTest.php`, using the real
  booted Laravel kernel/router lifecycle and synthetic fault injection without replacing the handler.
- Safe generic native response, bounded rendering, sole redaction-aware reporting ownership, final framework
  processing and sequential-request behavior.
- Affected safe-HTTP documentation and `CONTEXT.md`, preserving released public/native response contracts.
- John-approved prerequisite amendment: minimally propagate the configured 512-MiB PHPStan limit through the
  actual maintenance gate and reconcile safe reuse/retirement of its retained native database environment.
  Qualify this maintenance-compatible tooling directly, outside product suites; no whole develop tooling backport.

Out of scope: legacy handler/controller behavior changes, HTML sanitization, other framework adapters, consumer
routes/authentication/authorization, business retries/transactions, new schema or persistence, dependency-floor
changes, unrelated refactoring, packaging/release-process tests, certification, signing, publication and downstream
adoption. Separate reviewed forward-port integration must not import unrelated development changes.

## Use cases and contracts

Actor: a consumer explicitly composing Common's safe native Laravel exception handler. Trigger: a failure reaches
the selected JSON boundary and primary rendering, fallback rendering or an earlier diagnostic/projector operation
fails. Reporting and response construction are technical effects, not new business use cases.

| Use case | Commands | Queries | Events | Expected side effects |
| --- | --- | --- | --- | --- |
| JSON failure followed by rendering/encoding faults | N/A: no new business dispatch | N/A: no new reads | Existing Laravel lifecycle only | One original diagnostic attempt; bounded rendering; safe generic native 500 |
| Diagnostic sink fails before rendering | N/A: no business dispatch | N/A: no reads | Existing Laravel lifecycle only | No sink retry or false delivery claim; safe generic response even if ordinary fallback encoding fails |
| Final framework processing | Existing consumer workflow unchanged | Existing consumer workflow unchanged | Existing `RequestHandled` | Middleware/final response observers receive the safe response rather than an escaped renderer exception |
| Later independent request on the same handler | Existing consumer workflow unchanged | Existing consumer workflow unchanged | Existing Laravel lifecycle only | Reporting and normal rendering remain functional; no global suppression latch |

## Validation and permissions

Preserve explicit opt-in composition, `Request::expectsJson()` negotiation, successful category/status mappings,
validated native metadata and existing non-JSON delegation. Consumer authentication, authorization and redaction
policy remain consumer-owned; no new permission or endpoint is introduced. A terminal response must not copy the
original failure, renderer failure, causes, projected data or selected failure headers into public output.

Terminal construction must not depend on a failed encoder, projector or diagnostic sink. Prefer a minimal trusted
pre-encoded generic response through a compatible native construction path, subject to the released response
contract. Do not merely wrap the terminal fault in another exception, exhaust a finite retry budget, invoke raw
Laravel callbacks/logging or globally suppress unrelated future reports. This does not promise recovery from
process death, exhausted memory or arbitrary consumer middleware failures outside the owned rendering boundary.
