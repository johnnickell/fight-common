# Inspect and remove captured detail from configurable execution storage

detail through existing use cases against the configured execution storage supplied by TASK-00197. Complete the
record/inspect/remove path through existing Query/Command and guarded MCP composition without new protocol operations
or changed permissions. This TASK normally owns one PR and completes TICKET-00054's five-table capability.

  protected-detail permission, retained identity/retry guarantees and truthful missing/removed content projection.
- Extend actual execution inspection/protected execution/recording-removal fixtures and existing guarded MCP journeys

## Validation and permissions

Use the supplied ordinary-name validation/quoting in all identifier-bearing reader/join/subquery paths, preserving
bound filter/scope values and the existing finite-query/profile rules. Unsafe/unsupported/qualified configuration
rejects rather than becoming executable SQL or silent defaults. Table-name selection stays at consumer composition;
request fields, IDs or Tool arguments never select database tables.

Preserve current execution read, protected-detail read and removal permissions as distinct consumer decisions.
Safe-summary access is not content access, and table possession/selection grants no authority. Retain concealed/
unknown identity behavior, cross-project/session/phase isolation, relationship validation and safe public failures.
Removing content must not clear the retained identity required to prevent retries restoring it. Do not reinterpret
missing selected storage as successful migration, empty old history or proof of job completion/cancellation.
