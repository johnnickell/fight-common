# Record phase activity and measured usage

## Outcome

Trusted producers can durably record bounded phase activity and measured usage without conflating instrumentation,
performing Agent, model or authoritative Workflow state. Extend [TASK-00147](00147-TASK.md)'s recording path through
typed contracts, Commands, DBAL persistence and safe events, with the data required for deterministic later history
inspection. This is the second approved vertical slice of [TICKET-00040](../tickets/00040-TICKET.md).

Blocked by TASK-00147. No global execution priority is assigned; the dependency supplies the required session/phase
and persistence foundation. Approval covers planning only; map-wide TASK decomposition still precedes implementation
selection under the [map handoff](../wayfinder/mcp-execution-introspection-map.md#planning-handoff).

## Scope

- In scope: typed/versioned phase activity with observation identity, phase reference, producer, kind, safe summary,
  reported occurrence time and immutable server recording time; bounded namespaced consumer metadata.
- In scope: measured usage with units/provenance and honest unknown/partial/unavailable information; performing
  Agent/model/producer distinction, related persistence, admission, retries/conflicts and safe observation events.
- In scope: qualify recording-time/full UUID comparison agreement across application and SQLite/MySQL/PostgreSQL
  storage, plus schema evolution, documentation, compatibility and complete local verification.
- Out of scope: protected content capture (TASK-00149), public history/summary Queries and pagination
  (TICKET-00041), protected reads/removal (TICKET-00042), MCP/UI, usage estimation/billing policy, automatic
  instrumentation, Workflow mutations, outbox/replay, retention scheduling and OpenTelemetry.

## Use cases and contracts

Operation labels describe responsibilities; exact names and finite bounds are implementation details to document.

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Producer records activity within a permitted phase | Record phase activity through the existing Command bus | Internal phase/scope checks; no public inspection Query here | Safe committed activity fact | Persist typed activity and related database state atomically |
| Producer supplies measured usage | Record observation carrying measured usage | Internal relationship and measurement checks | Safe measured-observation facts within the chosen event catalog | Preserve actual value, unit, provenance and completeness without invented zero values |
| Delayed observation arrives or timestamps tie | Same activity recording Command | Storage reconstruction/comparison for conformance, not an inspection API | Same safe post-commit facts | Keep occurrence separate from recording time and preserve full deterministic UUID tie-breaker |
| Producer retries or delivery fails | Same recording Command under TASK-00147's contract | Retained identity/content comparison | Documented retry-event behavior; no guaranteed replay | Deduplicate/conflict safely; preserve committed activity despite later dispatch failure |

Do not create a second recording pipeline. Reuse TASK-00147's admission, version handling, transaction ownership,
producer-scoped retry comparison and post-commit failure distinctions, extending them for activity/usage data.
All writes related to one Command remain atomic, including retry identity and measurement relationships. Same
identity with changed activity or usage content conflicts rather than silently overwriting the original observation.

Store occurrence timestamps with their actual source precision, not invented precision. The downstream default
order is immutable server recording time descending, then full observation UUID COMB descending. Prove that database
and application comparison agree, including UUID random suffixes and tied timestamps. These keys are neither
causality nor a stable cross-transaction visibility boundary. This TASK supplies recording/comparison evidence;
TICKET-00041 still owns public Query ordering, live pagination and full-selection summary behavior.

## Validation and permissions

Use trusted current producer/scope admission on every recording/retry. Reject missing, mismatched or cross-project
phase/session relationships without leaking concealed records. Validate typed usage, units/provenance, versions,
finite summaries and namespaced extensions. Missing measurements stay missing; measured zero remains distinguishable.
Do not infer cost, context capacity, quota or outcome from another metric unless consumer evidence actually supplies
it under the defined type. Consumers own metric vocabulary and capture; Common enforces the documented structure.

Performing Agent, model identity and instrumentation producer cannot substitute for each other or confer authority.
Keep raw messages, tool arguments/results and process output out of safe activity, extensions, events and public
failures. Unknown outcome, partial measurement and unavailable evidence are explicit; no observation certifies
independent review or advances Workflow state. Structural checks do not universally detect secrets.

## Acceptance criteria

- [ ] Admitted activity and usage round-trip through the shared Commands and actual DBAL adapter on SQLite, MySQL
  and PostgreSQL, preserving typed versions, relationships, identity distinctions, units/provenance and unknowns.
- [ ] Invalid versions, fields, limits, usage representations and cross-scope relationships reject before success
  with no partial related writes or concealed-data disclosure.
- [ ] Concurrent same-content retries deduplicate and changed-content retries conflict for activity and usage,
  preserving original recording time and the retained-record guarantee from TASK-00147.
- [ ] Failure injection demonstrates atomic activity/usage/identity writes and rollback; post-commit dispatch or
  subscriber failure leaves committed records intact and is distinguishable from storage failure.
- [ ] Application and database ordering comparisons agree for recording-time/full UUID ties and delayed observations
  on every supported database; occurrence precision remains honest and no commit-order/causality claim is made.
- [ ] Safe events and public errors contain no protected bodies; observations do not mutate consumer Workflow state
  or treat absence of usage/completion as zero/success.
- [ ] Schema changes preserve TASK-00147 data, bus contracts and ordinary recording behavior; public additions are
  compatibility-classified. Document limits, usage meaning, comparison, retries and composition; align CONTEXT.md.
- [ ] Relevant tests, exact owned-code coverage and the complete local `./bin/build` gate pass with retained evidence.
