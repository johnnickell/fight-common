# Discover Authorized Resources Through the Guarded Endpoint

## Outcome

Deliver authorized Resource discovery through the existing guarded MCP `2026-07-28` endpoint. A consumer explicitly
composes providers, and a client receives only available Resource descriptors in bounded deterministic pages,
plus an empty complete URI-template list. This is one independently reviewable discovery PR, not a contracts-only
prefactor. Content reads and complete Resource acceptance belong to [TASK-00118](00118-TASK.md).

## Scope

- In scope:
  - Neutral provider/descriptor and request-scoped availability boundaries for metadata enumeration, separating
    discovery from content loading and preserving a compatible path to exact URI lookup in TASK-00118.
  - Explicit composition behind one owner of the Resource methods. Reject ambiguous URI ownership rather than
    use provider-order precedence; support multiple providers and non-filesystem URIs without automatic discovery.
  - `resources/list` with validated protocol metadata, availability filtering before deterministic pagination,
    bounded opaque cursors, and complete result/cache representation.
  - `resources/templates/list` returning an empty complete result, without a spurious continuation or a promise
    of URI-template resolution. Ordinary files containing templates are not URI templates.
  - Sensible finite defaults and optional validated overrides for URI/metadata/cursor/page processing and encoded
    discovery results; conservative private freshness defaults and explicit consumer-owned cache overrides.
  - Actual discovery/dispatch through the existing PSR HTTP handler, preserving Origin, invocation guard,
    authentication composition and standard/custom mirrors. No new endpoint or framework adapter.
  - Focused production behavior tests, applicable discovery conformance evidence, consumer documentation and
    compatibility-manifest classification for each new public declaration and promised behavior.
- Out of scope:
  - `resources/read`, file opening, text/binary encoding and raw-content budgets, which belong to TASK-00118.
  - Skills manifests or extension-ID merging, Tool discovery/invocation, URI-template resolution, subscriptions,
    listChanged, directory RPC, rendering, execution, filesystem mounts and automatic URL fetching.
  - Consumer identity/permission/catalog/storage policy, Agent OS/Pi implementation, new business messages,
    persistence schemas, production routes, release or deployment.
  - Shared bounded HTTP body reading and combined Tools/Resources/Skills acceptance, owned by
    [TICKET-00030](../tickets/00030-TICKET.md). No dependency on unfinished Tools, SSE or OAuth work.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Consumer registers several Resource providers | N/A; composition only | Validate provider metadata and URI ownership | N/A; no domain mutation | Accept explicit nonambiguous ownership or reject configuration; never scan arbitrary services/files. |
| Client lists available Resources through the guarded endpoint | N/A; read-only | `resources/list`; consumer-owned metadata enumeration | N/A; no domain mutation | Return filtered descriptors in deterministic pages without opening content. |
| Client resumes with a cursor | N/A; read-only | Validate cursor and enumerate the currently permitted continuation | N/A; no domain mutation | Continue safely or return a generic invalid-parameters failure; no concealed descriptors/counts. |
| Consumer changes availability between requests | N/A; policy change is external | Fresh injected availability during discovery | N/A; no Common permission event | Subsequent results reflect current decisions, independent of a connection or prior listing. |
| Client requests URI-template discovery | N/A; read-only | `resources/templates/list` | N/A; no domain mutation | Return an empty complete template list with valid cache metadata. |
| Origin, mirrors or invocation guard reject a request | N/A; no domain dispatch | Existing transport validation only | N/A; no domain mutation | No provider enumeration or content retrieval occurs. |

These protocol queries are not new Common CQRS Query classes. Providers may use consumer-owned queries; Common
introduces no business commands/events, schema migration or publication lifecycle. Diagnostics and any cache
operations are technical effects only. Authentication remains in the consumer's existing route composition.

## Validation and permissions

The availability collaborator receives neutral Resource metadata, not credentials, permission strings, a raw HTTP
request or a generic principal. The consumer closes over its current policy/context. Apply the decision before
protected metadata is exposed and before pagination; neither cursor possession nor an authenticated connection
confers visibility. Keep this decision boundary reusable by the later direct-read path.

Validate descriptor identity and protocol fields, including URI/MIME and applicable optional metadata. Validate
Unicode/JSON representation, bounds and complete provider output without opening files. Reject duplicate or
ambiguous URI ownership safely; do not reinterpret registered URIs into filesystem paths or network fetches.
Metadata enumeration must not require materializing the entire corpus or reading/hashing every file.

Validate cursor syntax, scope and size without leaking concealed identifiers. Preserve protocol-valid values,
including empty strings where permitted; absence of `nextCursor`, not truthiness, marks completion. Reject stale
continuations where the chosen provider/cursor contract cannot continue safely; ordinary restart needs no human
approval. Do not claim snapshot consistency across a changing catalog unless the provider supplies it.

Validate finite defaults/overrides and their relationships, including encoded discovery size. Reject excess rather
than truncate descriptors or produce a false complete result. Invalid parameters/cursors use central protocol-safe
errors; unexpected provider failures become generic internal errors with sanitized diagnostics. Do not return Tool
`isError` envelopes. Private cache reuse cannot bypass current availability or cross authorization contexts; only
the consumer may explicitly designate genuinely caller-independent public data. No new cache policy engine.
