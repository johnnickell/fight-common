# Summarize and inspect authorized retained notices

## Outcome

Authorized consumers can inspect full-selection notice summaries, bounded live history pages and selected notice
details through shared `QueryBus::fetch()` use cases. Deliver the complete summary → history → detail path with
current access, selection validation and actual DBAL reads in one normal PR, without a browser UI or live stream.

John approved this first vertical slice of [TICKET-00046](../tickets/00046-TICKET.md). Its only blocker is
[TASK-00158](00158-TASK.md), which supplies durable notices. [TASK-00161](00161-TASK.md) extends these shared read/
admission contracts for end-to-end recovery. Public removal, introspection, Prompts and live delivery are not blockers.

## Scope

- In scope: summary/list/detail Queries and handlers, shared current read admission, typed safe results, bounded
  selection validation and direct DBAL reads on actual SQLite, MySQL and PostgreSQL.
- In scope: full-selection statistics, topic/Agent/recipient/time/type filtering, permitted producer/author and
  causation details, live page/per-page semantics, safe failure/absence, compatibility, docs and complete verification.
- Out of scope: polling continuation/completeness and the MCP polling Tool (TASK-00161); recording/removal Commands;
  MCP subscriptions/current subscribers, Mercure, dashboards and consumer deployment qualification.
- Out of scope: asynchronous projections/Event Store dependency, frozen browsing, remembered searches, retention
  leases, browser navigation policy, protected bodies/full Task state and delivery/processing acknowledgment ledgers.

### Approved read mechanics

Read dedicated notice storage directly through inward-owned read contracts and DBAL adapters on all three accepted
databases. No asynchronous projection, separate ledger or unfinished introspection read implementation is required.
Consumers compose the same Queries for browser interfaces; presentation adapters must not perform competing SQL,
compute their own aggregates or decide a second permission policy.

Use stateless live `page`/`per_page` offset/limit pagination via `Pagination::strict()`, explicit filter/order field
allowlists, finite page/response/reference bounds and deterministic tie-breaking. Strict construction alone neither
authorizes fields nor makes arbitrary SQL identifiers safe. Totals/rows may change and rows may repeat or be skipped
across requests; no frozen results, remembered selections or page-reset behavior is promised. Ordering defaults,
allowed fields, time-filter meaning and tie-breaking remain implementation details to document precisely. Distinguish
occurrence/recording time and source precision; this history pagination is not the recovery continuation in TASK-00161.

Summaries cover all currently authorized matches. Count notices, not joined relationship rows or duplicate recording
attempts; intended-recipient/reference joins must not multiply totals. Apply access to aggregates as well as detail,
not by post-filtering a globally computed summary. Bound returned dimensions and avoid unbounded PHP materialization
or silent truncation while preserving full-selection meaning. Document consistency/freshness of summary and page
reads without claiming a snapshot across requests or complete capture of all application changes.

Support selection by topic, subject Agent, intended recipient, time and notification type. Return permitted
producer/author and causation references without conflating them with subject or audience. Broadcasts may have no
named recipient; unknown relationships remain explicit. A recipient field does not prove subscription, receipt or
processing. Preserve stable notice identity and safe supplied metadata without exposing internal global positions
or concealed history as incidental presentation fields. Protected messages/tool data/output, complete wire transcripts
and full MCP Task state are outside this feed.

## Validation and permissions

Consumers supply trusted current access/scope decisions, independent of caller-provided IDs, topic names, recipient
references, SUPER_ADMIN labels and prior successful reads. Human access does not imply Agent permission. Recheck
summary, every page and direct detail lookup; listing membership is not a detail grant. Apply the same selection/
admission rules to aggregates and rows, including metadata fields and permitted relationships.

Validate supported filters, input shapes, finite strings/lists, time bounds, positive representable pagination and
allowed ordering fields/directions. Define safe unknown/denied behavior without existence or private-diagnostic leaks.
Disappearing records are not evidence of expiry or proof that the caller saw them. Storage failure remains explicit
rather than an empty success. Consumer capture/redaction policy still owns safe source metadata; structural validation
is not universal secret detection. No mutation Commands/events or new identity/permission model belong to inspection.
