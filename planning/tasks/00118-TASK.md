# Read Exact Authorized Resource Content

## Outcome

Complete the authorized Resource read use case and [TICKET-00028](../tickets/00028-TICKET.md)'s list-to-read journey
through the existing guarded MCP `2026-07-28` endpoint. A client can request an exact registered URI independently
of listing membership, receive only authorized text/binary content, and observe safe failures when availability
changes or input/provider output is invalid. This is one independently reviewable feature PR, not a later testing
phase for [TASK-00117](00117-TASK.md).

## Scope

- In scope:
  - Exact registered URI lookup and lazy content retrieval using TASK-00117's provider composition/availability
    boundary, without a second owner of Resource methods or a competing provider registry.
  - `resources/read` with fresh authorization before content opening and safe indistinguishable failures for
    unknown and unavailable targets, including direct URIs not present in a listing page.
  - Protocol-complete results with truthful URI/MIME metadata, exact UTF-8 text, Base64 binary, valid empty-file
    content and conservative private cache defaults with optional validated consumer overrides.
  - Finite raw-content and encoded-result budgets consistent with discovery metadata and configured serving
    limits, including JSON/Base64 expansion, bounded retrieval and safe rejection without truncation.
  - Provider-result consistency, URI/path ambiguity rejection, failure handling and sanitized diagnostics; no
    silent byte conversion or URI-to-path/URL fallback.
  - A complete package-owned list/direct-read/template-discovery journey through the existing guarded endpoint,
    preserving Resource URI mirrors, Origin/guard ordering and consumer authentication composition.
  - Read-specific and integrated Resources conformance, compatibility classification, consumer walkthrough and
    full-gate evidence. Discovery evidence remains owned by TASK-00117 and is integrated rather than deferred.
- Out of scope:
  - Skills frontmatter/manifests/digests and whole-Skill rules, which belong to
    [TICKET-00029](../tickets/00029-TICKET.md); generic Resource reads do not create a catalog or revision store.
  - Tool Resource-link serialization and combined Tools/Resources/Skills acceptance; shared HTTP request-body
    limits remain in [TICKET-00030](../tickets/00030-TICKET.md), without making it a blocker here.
  - New endpoint/framework adapters, URI-template resolution, directory recursion/RPC, subscriptions/listChanged,
    rendering/execution, arbitrary filesystem serving, automatic URL fetching or production storage adapters.
  - Consumer identity/permissions/catalog policy, Agent OS/Pi work, mutation commands/events, schema migrations,
    production routes, SSE/cancellation/OAuth implementation, release and deployment.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Client reads a URI obtained through discovery | N/A; read-only | `resources/read`; exact provider lookup and current availability | N/A; no domain mutation | Open only the authorized requested content and return exact bytes in the correct wire representation. |
| Client supplies a registered URI absent from its list/page | N/A; read-only | Independent exact lookup, availability and read | N/A; no domain mutation | Authorized content is readable without requiring a prior list request or granting access from URI possession. |
| Client reads text, binary or an empty file | N/A; read-only | Bounded provider retrieval | N/A; no domain mutation | Return text or Base64 without normalization, rendering, execution or bulk prefetch. |
| Consumer denies a previously available Resource | N/A; external policy change | Fresh injected decision on the next list/read | N/A; no Common permission event | Deny new metadata/bytes even with a saved URI, cursor or cached descriptor; do not open content. |
| Client supplies an unknown/escaped URI or provider returns invalid content | N/A; no business dispatch | URI/output validation and safe error mapping | N/A; no domain mutation | Return a safe protocol failure; no arbitrary storage/network operation or truncated successful result. |
| Origin, Resource mirror, authentication composition or guard rejects the request | N/A; no business dispatch | Existing outer validation/guard only | N/A; no domain mutation | No protected content retrieval occurs. |

These are protocol reads, not new Common CQRS Query classes. Providers may use existing consumer queries. Common
adds no domain commands/events, schema changes, publication store or Workflow transitions. Diagnostics and any cache
operations are technical effects. Reading a template/script exposes bytes only and grants no authority to execute it.

## Validation and permissions

Resolve the exact registered identity through the shared unambiguous ownership boundary, then apply the same
current injected availability decision used by discovery before opening protected content. A prior listing is not
required and cannot authorize the read. Consumer authentication, permission interpretation and principal models
remain outside Common; pass only neutral Resource metadata into the availability contract.

Validate URI syntax, input bounds, provider identity and output representation. Do not normalize/decode repeatedly
into another registered target or follow traversal, redirect, URL-fetch or arbitrary filesystem fallbacks. For
file-shaped URIs prove registered-identity containment; no claim about arbitrary filesystem safety follows from a
neutral URI contract. Concrete storage adapters, if later added elsewhere, must prove their own containment.

Preserve exact original UTF-8 text, including Unicode and line endings; reject invalid text rather than silently
repair it. Binary representation is Base64 over raw bytes. Return a valid empty file as one empty text/blob content
item, not an empty `contents` array standing in for not-found. Check URI/MIME/size consistency where declared and
reject inconsistent provider output rather than serialize it as success. Resource reads do not infer immutability
or public access from a revision-looking URI.

Use safe central invalid-parameters responses for invalid/unknown/unavailable inputs without distinguishing denied
from absent Resources or reflecting protected paths. Unexpected provider failures become generic internal errors
with sanitized diagnostics. Preserve transport failures at their existing boundary; no Tool `isError` envelope.
Validate limits/overrides and their relationships before use, account for JSON/Base64 expansion, bound content
retrieval before unbounded buffering, and reject excess without truncating success. An accepted configured resource
must fit corresponding serving bounds; metadata alone is not a substitute for validating actual provider content.

Conservative private cache behavior and fresh authorization apply to direct reads. No cache reuse may cross
private authorization contexts or bypass a current decision. Public designation requires a deliberate consumer
assertion of caller-independent content; immutable bytes and freshness are not authorization. Common does not
promise to erase already disclosed client knowledge or build a generic cache/policy engine.

## Acceptance criteria

- [ ] The real Resource capability adds `resources/read` through the existing guarded handler, retaining one
  method owner and shared provider composition; no parallel dispatcher/endpoint is introduced.
- [ ] Authorized exact URI reads work both after discovery and without appearing in a prior page/list. Multiple
  providers route deterministically to one owner; ambiguous ownership never falls through to another provider.
- [ ] Unknown and denied reads have the same safe outcome. Changed availability is checked on subsequent direct
  reads, with content-access spies proving denied content is not opened; URI/cursor/cache possession grants nothing.
- [ ] Text, binary and empty-file responses have truthful URI/MIME/result/cache fields and exact byte evidence,
  including Unicode and CRLF. Invalid UTF-8 and inconsistent provider metadata/output fail safely.
- [ ] Traversal, encoded-identity ambiguity and arbitrary URL/filesystem fallback attempts do not escape registered
  ownership or trigger unintended I/O. Selected reads do not prefetch unrelated resources, render or execute files.
- [ ] Raw/encoded limits and overrides are finite and mutually valid. Boundary/over-limit tests account for
  JSON/Base64 expansion, bounded retrieval and discovery/read consistency without truncated successful content.
- [ ] Cache defaults/overrides, private-context separation and changed authorization are exercised; provider
  failures return central safe errors with sanitized diagnostics, not empty success or Tool error envelopes.
- [ ] Resource URI mirror checks, Origin, invocation guard and authentication composition retain existing behavior.
  Rejected requests cannot reach protected content retrieval. List, template discovery and read work in one fixture.
- [ ] Applicable pinned official Resources conformance checks cover the completed capability with nonempty and
  adversarial fixtures; source/version, per-scenario results and gaps are recorded honestly. Owned behavior tests
  fill harness gaps without claiming an unavailable or skipped required path passed.
- [ ] Each new public declaration and behavior is classified in `compatibility/manifest.json`; existing MCP/HTTP
  consumers and TASK-00117 discovery remain compatible. Documentation/`CONTEXT.md` cover the complete consumer
  composition, direct lookup, authorization, byte fidelity, bounds/overrides, cache/errors and deferred features.
- [ ] TICKET-00028's acceptance is mapped to both TASKs' evidence, including the guarded journey, conformance,
  compatibility, documentation, full `./bin/build` with exact owned-production coverage and independent acceptance.
  This completes Resources only, not EPIC-00007's combined Tools/Skills or downstream Agent OS/Pi acceptance.
