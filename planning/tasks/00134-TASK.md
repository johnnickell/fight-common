# Add Calendar and Local Time Values

## Outcome

Consumers represent calendar dates, local microsecond times and weekdays as distinct reusable concepts without
implicit timezone or native timestamp replacement. Deliver Date, Time and native WeekDay, their complete direct/
interoperability evidence and documentation in one independently reviewable PR under
[TICKET-00036](../tickets/00036-TICKET.md) and [EPIC-00008](../epics/00008-EPIC.md).

## Validation and permissions

Date supports years 0001–9999 and valid proleptic Gregorian month/day combinations. Canonical string is
`YYYY-MM-DD`; reject year zero/out-of-range, invalid month/day, non-leap February 29 and accidental normalization.
Leap-century behavior is Gregorian even before the historical calendar transition; no locale adoption policy.

Time supports hours 0–23, minutes/seconds 0–59 and microseconds 0–999999. Canonical representation has six fractional
digits, `HH:MM:SS.ffffff`. Reject 24:00, leap seconds, fractional overflow and silently normalized components.
Document supported factory spellings; final factory signatures are routine design within strict bounds, not
permission to inherit a permissive native parser. Do not use floating-point microseconds.

Native extraction uses supplied DateTimeInterface components, not process defaults. Copy scalar state rather than
retain mutable native input. A date/time alone has no zone or instant; do not invent midnight/default-date/native
conversion semantics or bypass the later strict zoned constructor.

Date/Time equality/hash follow same-concrete-type canonical representation; ordering follows chronological
components and returns -1/0/1 consistently with equality. Wrong-type equality is false; invalid construction or
wrong-type value comparison raises DomainException. WeekDay is a native backed enum, not a ValueObject/Identifier;
retain PHP-native invalid from() ValueError and tryFrom() null behavior rather than promising DomainException there.
