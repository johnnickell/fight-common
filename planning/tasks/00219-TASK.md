# Reduce subscription capacity-lock test cost

## Outcome

Shorten the largest measured Functional test matrix without losing meaningful evidence of subscription behavior.

## Scope

Profile the capacity-lock cases first. Map database, mode, transport, table configuration and delayed-bootstrap axes. Improve fixture or wait cost and consolidate cases only with an explicit account of lost assurance. No unrelated runtime behavior, gate policy or release changes.

## Use cases and contracts

A maintainer runs the existing subscription journeys through PHPUnit and reads timings and failures. No new package commands, queries, events or permissions; the test matrix may be smaller or faster.

## Validation and permissions

Keep meaningful framework and database coverage and exact 100% direct Unit coverage. Use disposable test data. Treat historical SQLite failures as unresolved unless reproduced; if repairing an identified product bug, follow the regression-first workflow separately unless already in approved scope.

## Acceptance criteria

- [x] Show comparable before/after case and suite timings, and identify which checks were kept, consolidated or removed and why.
- [x] Verify representative contention, timeout and recovery behavior and run the complete local gate with exact Unit coverage.

## Verification and evidence

Run focused subscription cases and `./bin/build`; retain logs, coverage and per-case timing. Record runs and failures, not just successful retries.

## Coordination

## Completion notes

The Functional capacity-lock matrix now runs 19 cases instead of 84. Every database (SQLite, MySQL and PostgreSQL) still runs all five outcomes: release before expiry, expiry during renewal, proposed lease elapsed, SQL timeout, and expiry before renewal. The test still uses an independent process and real SQL locks, checks stream output and stored state, and verifies retained Notice recovery. Both body reads and the response emitter, default and configured tables, and both bootstrap speeds remain represented on every database. Other subscription journeys, including native framework compositions, are unchanged.

The matrix no longer checks every transport/table/driver combination for every outcome. It drops 44 immediate-start and 21 delayed-bootstrap permutations. The remaining delayed cases cover both success and expiry, both transports and both table selections, rather than repeating every combination. This trades detection of faults unique to an omitted combination for lower runtime. The two immediate-start SQLite expired/body cases are unchanged; passing runs do not resolve the historical SQLite failure.

Fresh focused PHPUnit time fell from **8:37.897** (84 cases) to **1:52.676** (19 cases). The fresh local gate passed; Functional took **17:00.507** for 1,221 cases versus **20:53.529** for 1,286 in the prior local WF-049 run with equivalent application and test inputs at baseline. These suite runs were in different sessions and may reflect differences in load and resolved dependencies. The gate retained **19,304/19,304** exact direct Unit statements. The logs include a timed-out pre-change Functional attempt and the existing docs advisories.
