# Consolidate released MCP HTTP adapters under Mcp

## Outcome

Move the nine released public MCP HTTP adapter implementations to canonical `Adapter\Mcp` namespaces while keeping their existing names functional and deprecated throughout 1.x. John explicitly requested this bounded change and selected an isolated worktree. This is not authorization to move the Execution, Notice, Task or Subscription tracking subsystem or publish a release.

## Scope

- Canonical shared HTTP adapters: `Adapter\Mcp\Http\{DenyAllMcpOriginPolicy,ExactMcpOriginPolicy,McpOrigin,McpHeaderValidator,McpResponseEmitter,McpRequestHandler,McpResponseFactory}`.
- Canonical native adapters: `Adapter\Mcp\Symfony\McpResponseFactory` and `Adapter\Mcp\CodeIgniter\McpResponse`.
- Relocate the two internal HTTP helpers alongside their callers, without promising compatibility for internal names.
- Preserve old public construction, factory, method and native-response behavior without runtime deprecation notices. Keep concrete legacy class identity; use the established compatibility-subclass pattern where possible and an explicit immutable Origin compatibility implementation for its self-returning factory/private state.
- Migrate owned callers and mirrored tests; classify new declarations and update affected current documentation, changelog, context and ADR 0023's MCP-specific namespace amendment. Preserve historical records and existing release probes.
- Canonical compatibility parents are non-final solely to host final legacy classes; no consumer extension contract is introduced. Existing ports and authorization ownership do not change.
