# Integrate Safe Symfony Error Handling

## Outcome

A consumer explicitly selects safe Symfony error handling through its native exception lifecycle, receiving safe
JSend responses for JSON requests while preserving negotiation, native response types and legacy compositions.
Reuse TASK-00143's shared policy rather than introducing a Symfony-specific public-message/status policy.

John approved this complete feature TASK and its recommended contracts on 2026-10-06 under
[TICKET-00039](../tickets/00039-TICKET.md) and [EPIC-00008](../epics/00008-EPIC.md).
[TASK-00143](00143-TASK.md) is the direct blocker and carries the TASK-00142 vocabulary dependency. Laravel's
TASK-00145 is independent after that same blocker. No priority or worktree choice is assigned.

## Scope

- In scope: opt-in canonical Symfony error presentation and exception-event wiring, native responses, preserved
  JSON negotiation/non-JSON delegation, supported native HTTP failures and validated protocol metadata.
- In scope: shared public customization/validation policy, real lifecycle diagnostic ownership/redaction,
  regression-first containment, canonical and deprecated-path compatibility/migration, docs/CONTEXT.md,
  public classification, complete local verification and independent review.
- Out of scope: changing legacy constructors/default services/output in the minor, removing deprecated paths,
  replacing Symfony's HTML error renderer, activating a global Bundle/handler, application identity/authorization,
  permission names, business retries/rollback, MCP/OAuth changes and new persistence/schema behavior.
- Out of scope: Laravel integration, downstream repository migrations, wider framework/platform promises,
  release certification, packaging/release-process tests, publication and deployment.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Consumer opts into safe Symfony composition | N/A; container/event wiring | N/A; composition | Technical kernel.exception only; no domain event | Register the selected safe path without silently activating both legacy and safe listeners. |
| JSON controller/validation handling throws | Existing consumer command, if any | Existing consumer query, if any | Existing kernel exception event; no business event added | Produce a safe native JSend response with the shared category/status/data policy. |
| Supported native HTTP failure occurs | N/A; transport refusal | N/A; transport classification | Existing kernel lifecycle | Retain deliberate status and required validated metadata without exposing exception diagnostics. |
| HTML/non-JSON request fails | Existing workflow unchanged | Existing workflow unchanged | Existing kernel lifecycle | Preserve non-JSON delegation; do not falsely claim Common secures the delegated renderer. |
| Consumer migrates deprecated Symfony paths | N/A; composition | N/A; local configuration | N/A; no domain mutation | Opt into canonical safe handling; old public paths remain functional during the minor. |

Response creation/reporting are technical effects. Consumers own routes, principal resolution, authentication
challenge policy, permission checks, business failure intent and recovery; handling a failure does not roll back
previous command effects. This slice adds no business messages or database migration.

## Validation and permissions

Consume the complete [shared mapping and projection contract](00143-TASK.md#shared-mapping): AuthenticationRequired
401, PermissionDenied 403, ResourceNotFound 404, StateConflict 409, ResourceGone 410, PreconditionFailed 412,
InvalidInput/existing structured ValidationException 400, RuleViolation 422, RateLimitExceeded 429, ServerError/unknown
Throwable 500 and ServiceUnavailable 503. Expected refusals use fail; unexpected server/infrastructure failures use
error. Recognized categories and native HTTP failures still have fixed safe defaults, not getMessage() disclosure.

Define and document the exact supported native HTTP failure allowlist and its semantic/status translations. Include
supported routing, method/content negotiation, size and gateway outcomes at their HTTP owner, without converting
arbitrary timeouts to 504, storage lookups to 404 or authentication infrastructure faults to 401. Unrecognized failures
remain generic 500; integer exception codes and previous exceptions are not mapping authority. Preserve validated
consumer-owned authentication challenges, Allow for method failures and applicable Retry-After; reject malformed or
injected metadata and never indiscriminately copy HttpExceptionInterface headers. Do not invent a universal Bearer
scheme or a protocol-incomplete successful safe composition when required challenge configuration is missing.

Existing validation becomes safe fixed 400 output unless the consumer deliberately projects public field data.
Retain existing validation service and exception contracts. A category, validator message or raw getErrors() map
is not automatically safe. Custom presentation and serialization use the shared validation/fallback boundary.

Preserve established JSON preference/XHR behavior and delegation when HTML wins or JSON is not requested. Test
actual kernel status/header processing, not only direct controller calls: the framework can affect the final
response after an exception listener returns. Non-JSON reporting/rendering remains explicitly owned by the delegated
framework/consumer composition; no new HTML security promise is inferred.

Establish exactly one reporting owner in the supported Symfony wiring, including framework listeners and delegated
non-JSON paths. Test redaction before logger formatting, duplicate/lost reporting, and reporting/projection failures.
Production-safe handling is the new path's default. Any development details require explicit trusted configuration;
client headers/query/cookies or unrelated kernel/debug settings must not silently enable disclosure. Use the shared
behavior rather than a separate Symfony debug policy. An unavailable diagnostic sink is a documented failure, not a
claim that logging succeeded.
