# Inspect separately authorized captured detail

## Outcome

Humans and separately authorized Agents can retrieve bounded captured messages, linked tool arguments/results and
process-output chunks through shared application Queries. Deliver typed protected results, current detail admission,
handlers and actual database reads together as the first approved vertical slice of
[TICKET-00042](../tickets/00042-TICKET.md) under [EPIC-00009](../epics/00009-EPIC.md).

John approved two TASKs: protected reading, then authorized removal with integrated evidence. TASK-00149 supplies
separately database-backed bodies/links and capture metadata; TASK-00150 supplies reusable read infrastructure.
Reuse those implementations while adding separate current protected-detail authorization, never inheriting timeline
permission. Qualify direct DBAL reads on SQLite, MySQL and PostgreSQL. No global execution priority is assigned.

## Scope

- In scope: shared Queries for paginated messages, linked tool arguments/results and bounded process-output chunks,
  with content types, completeness and truthful absent-detail presentation.
- In scope: current permission on every page/chunk, relationship isolation, finite input/output bounds, live
  pagination, accepted observation ordering, actual DBAL reads, compatibility, documentation and verification.
- Out of scope: recording/capture, public removal (TASK-00154), filesystem/object storage, MCP, UI navigation,
  retention eligibility/holds/jobs, archival, hidden reasoning and guarantees of complete capture.

Preserve the existing Query bus and use the same application use cases for future MCP/dashboard composition. Do
not implement another content store or let an adapter reconstruct access policy. Collections use strict live
`page`/`per_page`; large individual bodies use bounded chunks, not unbounded results disguised as collection pages.
Validate chunk offsets/lengths or the chosen equivalent, including overflow and content boundaries. Preserve valid
text/byte semantics under the documented representation, with no accidental loss, duplication or invented content.
A partial captured segment is not necessarily the full process output; reaching its end does not prove complete capture.

Apply the accepted immutable server recording-time descending/full observation UUID COMB descending default to
observation collections. Preserve reported occurrence time separately with its actual precision. Qualify supported
microseconds and full UUID comparison agreement; no causal/commit-order or global checkpoint claim follows.
Each request independently supplies selection and rechecks access. Totals/pages may change; multi-page/chunk reads
have no frozen snapshot or retention lease and do not keep deleted bytes alive for an earlier browsing sequence.

Reuse TASK-00149's capture metadata and absence meanings. Preserve supplied partial/unavailable/expired information
where disclosure is permitted. An absent row alone cannot distinguish expiry from never captured or other absence.
Do not report a dangling reference as readable. Coordinate these meanings with TASK-00152's safe presentation without
requiring its Query implementation here; storage-level fixtures can prove absence before public removal exists.

## Validation and permissions

Consumer-supplied current decisions govern protected metadata and bodies for each page/chunk. Timeline access,
reference possession, prior successful reads or a human's permission do not authorize an Agent. Validate requested
scope, session/phase/activity/detail relationships, content kind, supported selection fields and finite limits.
Reject mismatched/cross-project references and invalid bounds without leaking concealed metadata or body content.

Safe outputs and public failures must not expose unauthorized captured data. No read mutation or domain event is
introduced. Storage failure cannot become successful empty content, and empty captured content must be distinguishable
from unavailable detail under the chosen result contract. Consumers retain authentication, permission policy,
capture selection and pre-submission redaction; structural validation is not a universal secret detector.
