# Create certification archives from pristine release content

## Outcome

Make the local release certifier install and qualify an archive created from pristine content at the exact
candidate commit, rather than from a dependency-installed, already-built directory. One standalone chore owns
one PR. John requested this task after the v1.3.0 archive limitation was explained; this record authorizes no
implementation, certification run or publication by itself.

## Evidence and original behavior

Before this TASK, `bin/release` exported the candidate into three temporary dependency lanes, resolved
dependencies and ran the complete product gate in each. It then ran the `archive-manifest` helper and
`composer archive` inside `DEFAULT_ROOT`, which already contained installed dependencies and generated build
output. The helper in `release/scripts/certify.php` added the requested version to the staging Composer manifest.
The consumer then installed this archive using an artifact repository and exercised the retained probe and
package-surface check.

The retained v1.3.0 certification at candidate `7de6cad6e8a9752973ad9f8e27e285b0c1510582` produced an approximately
422 MB local tar, including about 247 MB of `vendor/` and 138 MB of generated `var/` content. This weakened the
realism of local installed-consumer qualification; it did not demonstrate a consumer-runtime defect. The tar
was not uploaded. The published GitHub/Packagist distribution excluded those generated files, and a separate
registry-installed representative consumer probe passed. Historical release receipts remain under ignored
`.runs/handoffs/release-1.3.0-prep/` and
`.runs/handoffs/release-1.3.0-7de6cad6e8a9752973ad9f8e27e285b0c1510582/`.

## Scope

- In scope:
  - Separate pristine archive staging from all dependency-resolution and product-gate workspaces in `bin/release`.
    Export the exact candidate commit into an independent staging directory; retain the necessary local
    manifest version annotation without installing dependencies or running a build there.
  - Continue using Composer archive creation and the existing artifact-consumer installation, public behavior
    probe, package-surface inspection and candidate-bound certification record.
  - Preserve the three resolved dependency lanes, their complete gates, failure propagation and owned temporary
    workspace cleanup. Align `release/README.md` with the resulting archive provenance.
- Out of scope:
  - Log-retention changes, certification-record redesign, new release commands or release-process test suites.
  - Public runtime APIs, Composer dependency constraints, consumer authorization or framework behavior.
  - Unrelated package-content exclusions, public distribution policy changes or removal of tracked package files
    merely to reduce archive size.
  - Replacing historical artifacts/receipts, modifying published tags or releases, signing, pushing, registry
    publication or deployment.
