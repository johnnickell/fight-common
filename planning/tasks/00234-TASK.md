# Align signed request body integrity checks in Common

## Outcome

Callers using the Common signer and authenticator can rely on the same integrity rule for request bodies. This task targets the Common 2.0 candidate on develop. Maintenance-line patches follow the individual recommendations in [TASK-00233](00233-TASK.md).

## Scope and contracts

Work in the [request signer](../../src/Adapter/Auth/Hmac/HmacRequestService.php), [authenticator](../../src/Adapter/Auth/Hmac/HmacAuthenticator.php) and their existing tests. Use the signer's byte-string definition of an empty body. Preserve the signed message format, valid callers, empty-body behavior and existing authentication failure contract. This change adds no application commands, queries, events, permissions or data migrations.

## Acceptance criteria and verification

- [ ] Add focused regression coverage for the signer's and verifier's agreement on body boundaries. Valid signed requests still authenticate. The verifier rejects missing or mismatched integrity evidence for bodies that require it.
- [ ] Run the focused authentication tests and the repository's full build. Record exact revision, results and any compatibility impact. Align consumer guidance with the verified behavior.
- [ ] Obtain independent review and behavioral QA before recommending release. Mathias brings the candidate evidence and the maintenance-line dispositions to John for a tagging decision.
