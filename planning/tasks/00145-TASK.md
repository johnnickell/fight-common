# Integrate Safe Laravel Error Handling

## Outcome

A consumer explicitly composes safe Laravel error rendering/reporting with native responses and the shared public
projection policy, without automatically installing a global exception handler or changing legacy controller/provider
behavior. Deliver the complete integration, migration guidance and behavior evidence in one independently reviewable PR.

John approved this feature TASK and its recommended contracts on 2026-10-06 under
[TICKET-00039](../tickets/00039-TICKET.md) and [EPIC-00008](../epics/00008-EPIC.md).
[TASK-00143](00143-TASK.md) is the direct blocker and carries TASK-00142's vocabulary dependency. Symfony's
TASK-00144 is not a blocker. No execution priority or checkout/worktree choice is assigned.

## Scope

- In scope: opt-in canonical Laravel error presentation, explicit native rendering/reporting composition,
  shared safe category/public-data policy, supported framework failures and validated HTTP metadata.
- In scope: regression-first leak containment, real framework reporting/redaction ownership, legacy compatibility,
  concrete safe wiring, docs/CONTEXT.md, public classification, full verification and independent review.
- Out of scope: automatic global handler/provider activation, replacing Laravel authentication/authorization,
  consumer routes/identity/challenge policy, new permissions, business retries/transactions, Domain/Application
  HTTP fields, MCP/OAuth protocol changes and new schema/persistence behavior.
- Out of scope: Symfony integration, changing legacy defaults/constructors/services in the minor, mandatory
  downstream migration, expanded support floors, release certification, packaging/release-process tests and deployment.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Consumer chooses safe rendering/reporting | N/A; explicit composition | N/A; container configuration | N/A; no business event | Activate only the selected safe path; existing provider behavior remains unchanged. |
| Application handler throws a declared refusal | Existing consumer command, if any | Existing consumer query, if any | N/A; no invented domain event | Return a safe native JSON fail response with the shared category/status policy. |
| Supported framework failure reaches rendering | N/A; transport rejection | N/A; native failure classification | Existing framework lifecycle only | Translate supported intent and required metadata, not raw framework messages/context. |
| Unknown Throwable reaches the safe boundary | Existing workflow unchanged | Existing workflow unchanged | N/A; no mutation | Generic native 500 error response and one redaction-aware reporting path. |
| Consumer retains legacy composition | Existing workflow unchanged | Existing workflow unchanged | Existing workflow unchanged | Preserve published behavior while documenting its unsafe limitations and opt-in migration. |

Rendering and diagnostics are technical effects. Consumer authentication, authorization, routes, principal mapping,
challenge schemes and recovery remain outside this boundary. No rollback, event emission or retry is invented.

## Validation and permissions

Reuse the complete [shared mapping/projection contract](00143-TASK.md#shared-mapping): AuthenticationRequired 401,
PermissionDenied 403, ResourceNotFound 404, StateConflict 409, ResourceGone 410, PreconditionFailed 412,
InvalidInput/existing Common structured ValidationException 400, RuleViolation 422, RateLimitExceeded 429,
ServerError/unknown Throwable 500 and ServiceUnavailable 503. Expected refusals use JSend fail; unexpected
server/infrastructure failures use error. Both known and unknown failures have fixed safe public defaults.

Define/document the supported native framework failure allowlist and exact intent/status mappings, including native
authentication, permission, validation and supported HTTP method/rate-limit/routing/negotiation/size/gateway outcomes.
Do not conflate Common ValidationException's safe 400 contract with a native Laravel validation contract; document and
prove any supported native distinction explicitly. Neither native validation messages nor getErrors() are implicitly
safe. Only deliberate public projection can expose field data or custom messages.

Native status/header translation stays in Adapter and uses the shared policy where it matches. An arbitrary
HttpExceptionInterface implementation is not permission to forward unvalidated status/headers/messages. Integer codes,
previous causes, generic lookup/auth infrastructure failures and arbitrary timeouts do not establish client-failure
intent. Unknown failures use generic 500, not a guessed 404/401/504.

Validate consumer-configured authentication challenges, Allow for supported method failures and applicable retry
metadata; reject malformed/injected values. Do not invent Bearer as the universal challenge or silently omit required
protocol metadata. Optional retry-delay hints are not retry authority. Public data must serialize safely without
exception objects, entities, credentials or accidental diagnostic/code disclosure.

Choose one reporting owner in the actual Laravel report/render lifecycle. Rendering must not log a throwable again
if the configured reporting path already owns it; neither may framework reporting receive raw secrets before a later
redaction step. Test ignored/reportable failures, native transformations and delegation as relevant to the selected
composition. Redaction must precede logger formatting. Reporting/projection failures must not recursively report,
leak original diagnostics or masquerade as successful delivery to a failed sink.

Preserve framework negotiation/delegation and native response contracts. Production-safe behavior is the new path's
default. Any development disclosure uses explicit trusted configuration, not request input or accidental inference
from unrelated Laravel/environment settings. Shared customization/fallback behavior must not drift between frameworks.
Legacy controller behavior and HttpServiceProvider's capability-scoped registration remain functional and unchanged.

## Acceptance criteria

- [ ] Deliver explicit canonical Laravel safe rendering/reporting wiring using the shared policy and native
  Illuminate responses; no automatic global activation or silent replacement of existing services/constructors.
- [ ] Begin with meaningful failing synthetic-secret regressions for the safe-handling contract, retaining separate
  legacy disclosure reproduction/assertions. A missing class/setup failure is not containment evidence, and legacy
  defaults remain explicitly unsafe rather than falsely claimed repaired.
- [ ] Exercise a booted Laravel application's actual report/render journey with throwing handlers, not only direct
  ErrorController calls. Assert every application category/subtype, RuntimeException/PHP Error, exact native status,
  JSend shape and absence of sensitive messages, causes, context, codes and raw validation data.
- [ ] Document/test the native failure allowlist, native validation distinction, negotiation/delegation and supported
  auth/permission/method/rate-limit/HTTP outcomes; do not install an implicit generic lookup/auth/timeout mapping.
- [ ] Prove safe public/field-data customization, required validated challenge/Allow/retry metadata and malformed/
  injected metadata rejection, including final framework processing of the rendered response.
- [ ] Prove one owned redacted diagnostic path in the actual reporting/rendering order, including expected failures
  the framework would otherwise ignore, unexpected failures, projector/serialization/reporter failure paths and no
  duplicate logging or raw secrets reaching logger formatters.
- [ ] Prove production defaults and no client-controlled debug; if development details are offered, prove explicit
  trusted opt-in separately and preserve production fallback sanitation.
- [ ] Preserve legacy ErrorController output/constructor/native type and HttpServiceProvider registration behavior;
  demonstrate opt-in migration without changing an existing consumer merely by installing the minor update.
- [ ] Classify declarations/wiring/output/reporting under ADRs 0009–0011. Document concrete Laravel opt-in wiring,
  report/render ownership, exact mappings/headers, safe data policy, unsafe legacy deprecation and planned major-default
  migration in affected HTTP/framework/validation guidance and CONTEXT.md.
- [ ] Complete focused behavior/integration checks and full ./bin/build with exact owned-production coverage,
  actual results/warnings and tested-content receipt suitable for independent review.
