# Organize MCP tests around observable contracts

## Outcome

Make direct MCP responsibilities and security-sensitive Task scenarios easier to locate and understand without
weakening behavior evidence. Separate focused direct subjects from responder journeys; expand compressed Task
revision/cancellation scenarios. Normally one test-only PR.

John approved planning this recommendation on 2026-11-02 after the architecture report at develop `521a71c`.
Planning does not authorize implementation or publication; production behavior is not changed by this chore.

## Scope

- In scope: direct subjects currently collected in `tests/Application/Mcp/McpResponderTest.php`, retained
  integrated semantic responder journeys, and readability of `TaskRevisionTest`/`TaskCancellationTest`.
- Mirror actual source paths, keep accurate suite membership and direct coverage metadata, and preserve reusable
  fixtures where they serve the same knowledge. Follow source moves already present when work starts.
- Repair current runnable-test-path documentation only where affected.
- Out of scope: production changes, a test framework rewrite, widening into every MCP test, assertion weakening,
  new source-text/tooling tests, package/release-process tests or deleting unique contract evidence for neatness.

implementation under test. Consumer authorization and actual effect ordering stay unchanged.
