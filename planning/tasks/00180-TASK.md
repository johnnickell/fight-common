# Organize MCP tests around observable contracts

## Outcome

Make direct MCP responsibilities and security-sensitive Task scenarios easier to locate and understand without
weakening behavior evidence. Separate focused direct subjects from responder journeys; expand compressed Task
revision/cancellation scenarios. Normally one test-only PR.

John approved planning this recommendation on 2026-11-02 after the architecture report at develop `521a71c`.
Planning does not authorize implementation or publication; production behavior is not changed by this chore.

## Scope

- In scope: direct subjects currently collected in `tests/Application/Mcp/McpResponderTest.php`, retained
  integrated semantic responder journeys, and readability of `TaskRevisionTest`/`TaskCancellationTest`.
- Mirror actual source paths, keep accurate suite membership and direct coverage metadata, and preserve reusable
  fixtures where they serve the same knowledge. Follow source moves already present when work starts.
- Repair current runnable-test-path documentation only where affected.
- Out of scope: production changes, a test framework rewrite, widening into every MCP test, assertion weakening,
  new source-text/tooling tests, package/release-process tests or deleting unique contract evidence for neatness.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Maintainer locates a decoder, metadata, registry, mirror or response contract | N/A; test organization | N/A | N/A | Find a focused test subject without searching unrelated responder cases. |

| Maintainer reviews a Task permission/expiry/failure scenario | Existing payloads unchanged | Existing payloads unchanged | Existing facts unchanged | See setup, action and expected state/effect without compressed multi-statement lines. |

The chore introduces no new product Commands, Queries, events, storage/schema changes or runtime effects.

## Validation and permissions

Preserve evidence for concealed/unknown identities, current permissions, usable request IDs, immutable JSON
shape, metadata budgets, Task revisions/expiry, cancellation meaning and committed-but-dispatch-failed outcomes.
Tests must not replace these cases with happy-path mock sequences or derive expected results from the same
implementation under test. Consumer authorization and actual effect ordering stay unchanged.

## Acceptance criteria

- [x] Direct decoder, metadata, registry, mirror, result/error/response subjects have clear focused homes as
  warranted by actual responsibility; responder tests retain useful integrated journeys.
- [x] Sampled Task revision and cancellation cases use readable setup/actions/assertions, retaining causal detail.
- [x] Existing meaningful expectations are retained or have documented equivalent contract coverage; no unique
  boundary/security/failure evidence disappears.
- [x] Every test class has appropriate coverage metadata and all direct subjects retain exact required coverage.
- [x] Suite membership, fixtures and runnable references are accurate; there is no production/API change.
- [x] Focused/full checks, equivalence assessment, warnings and independent Review/QA evidence are recorded.
