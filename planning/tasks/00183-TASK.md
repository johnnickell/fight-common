# Codify aggregate-first architecture and descriptive naming rules

## Outcome and accepted decision

John approved bounded architectural correction on 2026-11-02 after reviewing the recent MCP additions at
`77237f6741af`. Record his requirements as project-owned engineering guidance before the dependent refactors.
This is a standalone documentation chore, normally one PR; it does not reopen completed feature records.

The accepted direction is Domain-owned aggregates, identities, repositories and invariants; Application handlers
own use cases through separate repository and transaction contracts; adapters own persistence and presentation.
John explicitly rejected broad lifecycle forwarding services, accepted separating Task disclosure encoding from
Domain state, and required value objects to extend the existing `Domain\Value\ValueObject` base.
Variable names must fully identify their responsibility: `$taskRepository`, not `$tasks`; likewise `$queryBus`,
`$commandBus` and `$eventDispatcher` for those collaborators. This applies throughout project-owned code, not
only new MCP classes. The follow-up implementation records are TASK-00184 through TASK-00192.

## Scope

- Update the local Architecture and Naming standards, project profile and applicable CONTEXT/architecture guide
  descriptions. Keep a single normative owner for each rule and link it from entry instructions as needed.
- Specify `Domain/{BoundedContext}/{Aggregate}` with aggregate root, aggregate identity, repository interface,
  nested entities/value objects, verb-first Command/Query and past-tense Event branches. Domain services/DTOs
  need a demonstrated Domain responsibility; do not use them as miscellaneous technical buckets.
- Specify matching Application aggregate ownership with CommandHandler, QueryHandler, policy-named
  EventSubscriber and meaningful capability subnamespaces; Service is a fallback, not the aggregate root folder.
- Specify capability-first adapters, aggregate-oriented persistence and concrete MCP Tool presentation in Adapter.
  Retain the approved `Adapter/Mcp` umbrella; do not introduce speculative protocol-version folders.
- State that value objects extend ValueObject directly or through a meaningful existing value base. Immutable
  entities, DTOs, native enums and technical ports are not automatically value objects.
- Preserve explicit package exceptions: shared low-level primitives, Standards' orthogonal layer, Application MCP/
  JSend semantics, portable container, the exact CronExpression allowance, Scheduler's released compatibility
  bridge and required released namespace bridges. New exceptions require an owned reason and decision.
- Reconcile ADR 0023 visibly where new Tool/persistence destinations specialize it; preserve historical decisions.
  Record the local standards amendment and updated affected digests in `docs/engineering/STANDARDS.md`.
- Out of scope: production refactoring, automatic synchronization of upstream guidance, changed dependencies,
  blanket external-effect rules, new permission policy or removal of released APIs.
