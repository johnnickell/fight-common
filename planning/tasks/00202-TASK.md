# Qualify ORM table overrides and complete the inventory

## Outcome

Demonstrate that existing nonce and audit repositories honor native ORM mapping-based table overrides with real
persistence, retaining defaults and one metadata authority. Reconcile the full Common-owned table inventory with
completed naming suppliers so no state/lock, data or mapped table is omitted. This finite runtime-compatibility and
completeness slice normally owns one PR; it is not package/release certification or a second naming API.

## Scope

In scope:

- Existing `nonces` and `audit_entries` mappings/repositories, default behavior and consumer-selected native ORM
  metadata/mapping overrides. Use actual ORM construction and database operations, not only mocked metadata/SQL.
- Nonce consumption/uniqueness and expired purge; audit persist/flush/reload and actor/action/inclusive timestamp
  queries, using existing Doctrine types and current repository contracts.
- Preserve the native ORM mapping extension point, existing supported naming/configuration behavior and database
  type/serialization/transaction promises. Do not apply new DBAL-only naming restrictions retroactively to ORM.
- Inspect current Common source and reconcile nineteen DBAL plus two ORM tables from the initial EPIC inventory,
  mapping each schema/runtime path to the actual supplier implementation and relevant accepted evidence.
- Complete consumer-facing naming/ownership/no-migration documentation and affected CONTEXT.md descriptions;
  document framework/provider and fixture tables as distinct owners, not missing Common implementations.

Out of scope: competing config objects/registries for ORM, speculative repository/ORM redesign, new domain behavior,
new permissions, new platform floors, migrations/automatic renames/data transfer, supplier reimplementation,
automated Markdown/source-text inventory tests, packaging/release tests, certification or unrelated fixes.

## Validation and permissions

ORM metadata remains the authority for these table names, including supported native mapping configuration. Add
no second ordinary-name validator that removes existing released ORM support. Keep actual identifier handling and
value binding compatible with the ORM/DBAL contract; verify raw-SQL nonce paths honor selected metadata rather than
assuming ORM DQL coverage proves them correct. Preserve current nonce exception families and audit query bounds.

Consumers retain connection/schema selection, database privileges, authentication/replay policy and audit admission/
read permissions. Table selection grants none of them and adds no public endpoint. Configuration does not move old
records, reset replay protection or establish that an audit history is complete. A demonstrated mapping defect is
reported with a meaningful reproducer; any repair must remain within the accepted compatibility promise and begin
with a failing regression, not become speculative broader cleanup.
