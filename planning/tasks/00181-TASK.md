# Classify MCP foundation namespaces with released-name compatibility

## Outcome and accepted decision

Introduce coherent canonical MCP foundation namespaces without removing supported released entry points.
John explicitly chose the additive migration on 2026-11-02: deprecate **only relocated old names that actually
appeared in a tagged release**, keep them functional, and remove them only in a separately authorized future
major after the required released-minor deprecation window. Never-released names move directly without
snapshot aliases or deprecations. The two root declarations that do not move are not deprecated.

This supersedes the architecture report's default suggestion to wait for a major before adding the canonical
names. Public interface redesign and Scheduler changes are out of scope. Normally one compatibility-preserving
PR; no tag/version, removal, implementation or publication is authorized by this planning record.
