# Adopt the EPIC, TICKET, and TASK planning surface

## Outcome

Adopt EPIC → TICKET → TASK with consistent Boards and generated status views. This standalone chore is the first
adoption trial before applying the conventions elsewhere.

## Scope

- Migrate 22 archived PRDs to TICKETs and 95 archived executable tickets to TASKs, preserving numeric identities,
  terminal statuses, outcomes, parent relationships, and dependency meaning.
- Preserve five EPICs and WF identifiers; repair links and provide an old-to-new map.
- Update conventions, templates, indexes, Board, Roadmap, agent instructions, validation, and archive tooling.
- Exclude product PHP changes, immutable release receipts, runtime enrollment, production effects, skill
  installation, and migration of other repositories. Keep the existing canonical product checks; use `composer update` in the build as required for this library's ignored lockfile.

## Validation and permissions

The user authorized this migration including archives and selected the main checkout on a feature branch.

Planning tools validate identifiers, parents, dependencies, cycles, terminal archive eligibility, and generated
views. Immutable receipts and external historical references retain their original identity, documented by the map.
