# Make Validation Reuse Exception-Safe

## Outcome

A consumer can reuse the same ValidationService or ValidationCoordinator after a failed invocation without running
stale validators/rules or receiving errors belonging to that earlier operation. Preserve the original throwable,
ordinary validation results and existing public service/coordinator contracts. Deliver the repair, regressions,
compatibility assessment and documentation as one independently reviewable PR under
[TICKET-00031](../tickets/00031-TICKET.md) and [EPIC-00008](../epics/00008-EPIC.md).

John approved this single-TASK decomposition on 2026-10-06. This record authorizes planning, not implementation,
publication or release. There are no TASK blockers and no dependency on the new Application error vocabulary or
HTTP handling. No execution priority has been assigned.

## Scope

- In scope: invocation-state cleanup owned by ValidationCoordinator/ValidationService, including thrown validators
  and service input/rule preparation failures involving queued validators. Keep the consumer-supplied coordinator
  and custom-validator registration behavior; do not replace the injected instance to conceal stale state.
- In scope: meaningful direct coordinator and service regressions, preserved result/exception behavior, behavioral
  compatibility classification, affected validation documentation, CONTEXT.md and any necessary API classification.
- Out of scope: new rules or exception categories, HTTP error presentation/redaction, changes to Symfony wiring,
  authorization, concurrency/reentrancy guarantees, custom-validator side-effect rollback, persistence/schema
  changes, architectural reorganization, dependency/support changes, release tooling or packaging tests.

## Use cases and contracts

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Consumer repeatedly validates valid or invalid input | N/A; existing local validate call | N/A; no CQRS read | N/A; no domain mutation | Produce each invocation's own ApplicationData or structured failure and clear its queued validators. |
| A custom validator throws an Exception or PHP Error | N/A; existing local validate call | N/A; no CQRS read | N/A; no domain mutation | Propagate the original throwable unchanged; clear pending validators/rules before reuse. |
| Input/rule preparation rejects an invocation with queued validators | N/A; existing local validate call | N/A; no CQRS read | N/A; no domain mutation | Preserve rejection behavior and prevent queued state from affecting a subsequent invocation. |
| Consumer retries with unrelated input and empty or new rules | N/A; existing local validate call | N/A; no CQRS read | N/A; no domain mutation | Only current invocation validators/rules execute; no stale errors or old field requirements. |
| Consumer injects a coordinator and adds custom validators | N/A; existing composition/registration | N/A; no external lookup | N/A; no domain mutation | Preserve the injected collaborator and intended one-invocation validation behavior. |

These are local technical effects, not new business commands, queries, events or external delivery. A new
ValidationContext already belongs to each coordinator call; the demonstrated defect is retained validators that
run against the later context, not a shared error map requiring a new storage mechanism. Common cannot undo
consumer-defined validator effects. No database, migration, authentication mechanism or new permission is needed.

## Validation and permissions

Preserve existing input-key and rule-format validation, rule semantics and structured ValidationException errors.
An ordinary invalid result must not become an unexpected runtime failure; an unexpected throwable must not become
success or an ordinary field error. Cleanup must not wrap, swallow or replace the original throwable, lose its
integer code/previous cause, or trigger another validation of the failed input merely to drain pending state.

Invocation cleanup also covers failures before the coordinator's validate call when custom or prepared validators
are queued. Preserve predictable rejection of malformed input/rules; this repair does not require stricter parsing,
new exception families or clearing consumer-owned validator internals. Authorization is N/A to the capability and
remains consumer-owned. Validated input is not sanitized or authorized, and exception diagnostics are not made
safe for public presentation by this repair; [TICKET-00039](../tickets/00039-TICKET.md) owns that other boundary.
