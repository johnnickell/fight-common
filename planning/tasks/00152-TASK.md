# Inspect phase activity and safe detail references

## Outcome

Humans and authorized Agents can inspect bounded phase activity and permitted protected-detail references without
retrieving protected bodies. Deliver the typed safe results, Query handlers, current authorization and direct DBAL
reads as the third approved vertical slice of [TICKET-00041](../tickets/00041-TICKET.md).

[TASK-00150](00150-TASK.md) supplies reusable read contracts/admission, and [TASK-00149](00149-TASK.md) supplies
protected-detail links and truthful capture metadata atop the session/phase/activity recording path. There is no
dependency on TASK-00151's execution/phase browsing or on TICKET-00042's public protected read/removal APIs. John
approved initial direct DBAL reads qualified on SQLite, MySQL and PostgreSQL, not asynchronous projections or an
Event Store dependency. No global execution priority is assigned.

## Scope

- In scope: bounded safe phase activity Queries, permitted detail references, capture/availability metadata,
  current access, validated selection and recording-time/full UUID ordering on all three supported databases.
- In scope: real DBAL implementation, safe removal/absence presentation using storage-level fixtures, compatibility,
  documentation and complete local verification.
- Out of scope: protected bodies, public protected read/removal Commands/Queries, retention eligibility/jobs,
  automatic capture/redaction, MCP/UI, Workflow authority, browsing sessions and guaranteed event recovery.

## Use cases and contracts

Operation labels describe behavior, not predetermined public PHP names.

| Use case | Commands | Queries | Events | Expected side effects |
|---|---|---|---|---|
| Caller inspects a permitted phase's activity | N/A; read only | List phase activity through `QueryBus::fetch()` | N/A | Return bounded ordered safe activity and permitted references |
| Caller inspects a reference's safe capture metadata | N/A; read only | Same activity Query; no body retrieval here | N/A | Preserve permitted completeness/availability information without implying a body-read grant |
| Access changes or detail disappears before the next page | N/A; read only | Repeat activity Query with current admission | N/A | Safe current results, truthful absence or denial; no retained-content lease |
| Delayed evidence arrives or recorded timestamps tie | N/A; read only | Same bounded activity Query | N/A | Deterministic recorded-time/full UUID ordering, not chronology or commit order |

Reuse TASK-00150's current read admission and bounded Query contracts; do not add a parallel permission policy or
recording implementation. Default activity ordering is immutable server receipt/recording timestamp descending,
then full observation UUID COMB descending. Preserve reported occurrence separately with actual source precision.
Qualify microseconds and database/application comparison agreement, including the complete random UUID suffix.
These keys are neither a causal sequence nor a safe global checkpoint. Retries cannot reset recording time.

Each call independently supplies selection, strict page/per-page pagination and supported filter/order fields.
Finite page/response limits apply to metadata and reference collections as well as activity rows. Data changes may
repeat or skip rows across pages; no frozen results or remembered browsing exist. Freshness refers to stored evidence
read, not complete capture or authoritative execution state.

Safe references and capture metadata remain permissioned. Never advertise a dangling/missing body as available,
claim a reference grants later access or confuse retained content with current permission to retrieve it. Preserve
supplied partial/unavailable/expired information only where disclosure is permitted; absence alone cannot establish
expiry or never-captured status. Reuse TASK-00149's retained metadata semantics and coordinate those same meanings
with TICKET-00042, which owns separately authorized body retrieval and public removal. Do not duplicate those APIs
or introduce a reverse dependency merely to test safe absence presentation.

## Validation and permissions

Apply current consumer-supplied decisions to phase/session relationships, activity rows and detail references;
IDs, previous pages and timeline permission do not grant body access. Reject guessed/cross-project references and
invalid bounds/fields safely. Keep performing Agent, model and producer distinct and do not imply independent
review acceptance from activity labels. Human permissions do not implicitly authorize Agents.

Raw messages, tool arguments/results and process output must never appear in safe activity, reference metadata or
public failures, including after removal or storage error. This is structural separation and enforcement of supplied
access decisions, not a universal redaction service. Queries do not mutate data or emit domain events.
