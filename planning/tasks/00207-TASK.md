## Scope and audit finding map

### 1. Complete the compatibility manifest — high

`compatibility/manifest.json` omits these documented consumer declarations:

- `Adapter\Persistence\Doctrine\DbalTableName`
- `Adapter\EventSourcing\Dbal\DbalEventStoreTables`
- `Adapter\EventSourcing\Dbal\DbalPublicationFailureTables`
- `Adapter\Mcp\Persistence\Execution\Dbal\DbalObservationTables`
- `Adapter\Mcp\Persistence\Notice\Dbal\DbalNoticeTables`
- `Adapter\Mcp\Persistence\Subscription\Dbal\DbalSubscriptionTables`
- `Adapter\Mcp\Persistence\Task\Dbal\DbalTaskTables`

Names are relative to `Fight\Common`. Classify their actual promised operations intentionally, with source-linked
authority and rationale, rather than marking public APIs internal to pass inspection. Reconcile the entire
current inventory, public members and operation-shape SHA-256 after runtime repairs, not just these seven rows.
The intake manifest expects 229 Domain declarations but already contains 233 Domain declaration rows; the audit
also reports stale counts/digest. Derive final counts and shapes from the existing structural inventory.

`release/src/Adapter/PackageSurfaceInspector.php` rejects unclassified declarations, mismatched counts and
operation shapes. Retain those checks and the existing baseline/package promises unchanged. Do not weaken the
certifier, narrow the inventory or add packaging/release-process tests. Public table-selection contracts are in
[the table guide](../../docs/table-names.md).

### 2. Restore released HMAC constructor names — high

`src/Adapter/Auth/Hmac/HmacAuthenticator.php` currently accepts `nonceRepository:`; canonical `1.1.0` published
`nonces:`. Source/tag evidence reports that historical named construction now raises an unknown-named-parameter
error, while positional injection works. Preserve both released spellings and the existing positional sequence,
and ordinary authentication/replay behavior. The repository is optional in both the canonical `1.1.0` source
(commit `1666dbaa503e40ea2fc652bccbeba22e6cda6b70`) and the current constructor: omission/null must keep working,
without newly requiring replay storage or implying that omitted storage provides replay protection.

Define and document deterministic dual-input handling: null means no supplied repository; one non-null repository
selects that instance; both spellings referring to the same instance agree and consume only once; distinct
non-null repositories reject before authentication or repository effects rather than silently selecting one.
Add meaningful constructor/authentication regression coverage before repair in
`tests/Adapter/Auth/Hmac/HmacAuthenticatorTest.php`, using actual tagged signatures as the authority rather than
only current positional fixtures.

### 3. Preserve tagged Tool-output backward reads — medium

`src/Application/Mcp/Tool/McpToolOutput.php` adds a readonly response-budget field absent from native serialized
outputs produced by `v1.3.0`/`v1.4.0`. Unserialization bypasses construction; the invoker's budget getter can then
read an uninitialized property and turn a valid output into an internal error. Newly constructed output tests do
not prove backward reads. The released-root `McpResult` contains an analogous absent-field compatibility pattern.

Treat an absent historical budget as null/unbounded without changing saved identities or structured content,
text, links and current bounded-output behavior. Add a trustworthy tagged native-output fixture with its origin
recorded, and exercise the restored output through ordinary Tool invocation, not only an isolated getter.
Do not normalize away a real present budget or use a newly serialized current object as historical evidence.

### 4. Contain Tool-discovery availability failures — medium

`src/Application/Mcp/Tool/McpToolRegistry.php` lets availability callbacks propagate `McpProtocolException`;
`McpResponder` treats that exception as an intentional public protocol failure. Unexpected availability failures
can therefore disclose supplied error data and skip central diagnostics. Ordinary RuntimeException coverage is
not sufficient counterevidence; compare the existing stronger invocation/Resource/Skill containment.

Add a failing responder-level `tools/list` regression where availability throws a protocol exception containing
private sentinel data. The corrected result must be the documented generic internal error with no supplied
message/data disclosure and exactly one central diagnostic record for the original failure. Preserve intentional
protocol validation errors, fresh availability evaluation and unknown/hidden Tool behavior; add no authority cache.
