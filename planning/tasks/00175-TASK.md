# Make PHPStan's memory budget explicit

## Outcome

Make the build and focused PHPStan commands use an explicit 512M per-process memory budget so local static
analysis does not depend on an implicit interpreter limit. Investigate the historical 512M/128M discrepancy and
verify the effective parallel-worker budget. This bounded development-tool repair owns one PR, not a package release.

John approved this scope and standalone TASK creation after the diagnosis draft, then explicitly invoked
Build TASK-00175 in the main checkout. That invocation supersedes the earlier planning-only authority and pending
checkout choice. Work uses `feature/task-00175-phpstan-memory-budget` from develop in the main checkout; Build
coordinates later independent Review, QA and authorized Land publication. No execution priority or dependencies
have been assigned. Implementation remains non-terminal pending independent Review and required QA.

## Diagnosis and reproduction

The saved full build for [TASK-00149](00149-TASK.md), associated with PR #224, exited 1 because PHPStan reported
`configured PHP memory limit: 128M` while running a parallel worker. The failure prevented later gate stages.
Its retained local evidence is `.runs/tasks/TASK-00149/runs/land-ci-fix-20261022T235657Z/`, particularly
`full-build.log`, `full-build-context.txt`, `full-build.exit` and `receipt.md`.

That run used `./bin/build` in a detached checkout at `6388ea787494caa4e81b8391f536f49510d69b89`, with the
receipt's two planning-link corrections, ordinary dependency resolution and PHPStan 2.3.1. It ended with image
`sha256:b2d6ce5b384eea09e8ffdaca4e8eff23480374402380dc807e96224d9c613311`.

Diagnosis at clean develop revision `02a68244ae9c8c71fc7bc2cda2764d14f12c2ce0` established:

- `bin/quality` and `bin/phpstan` invoke analysis without an explicit memory budget; `bin/build` invokes `bin/quality`.
- `etc/docker/php/local.ini` specifies 512M. The existing image above reports PHP 8.5.12 and `memory_limit=512M`;
  the installed PHPStan version is 2.3.1.
- Each of the following commands ran in a fresh disposable container with a read-only checkout and networking
  disabled. Both exited zero, explicitly reported a missing result cache, analysed 708 files, and used ten forked
  workers. Largest-worker peaks were 146 MB without the flag and 150 MB with it.

```bash
docker run --rm --network none -v "$PWD:/app:ro" -w /app fight-common \
  php vendor/bin/phpstan analyse --no-progress -vvv

docker run --rm --network none -v "$PWD:/app:ro" -w /app fight-common \
  php vendor/bin/phpstan analyse --memory-limit=512M --no-progress -vvv
```

Expected: complete analysis within the intended budget, with consistent worker configuration.
Observed: the historical 128M worker failure is confirmed by its saved log, but did not reproduce in either
current cold-cache run. These successful runs are not a repaired full gate or proof of each worker's exact limit.
The inspected diagnostic container had no cgroup memory maximum and no recorded OOM events; that does not establish
the failed run's aggregate-memory conditions. The command configuration gap is confirmed; the historical cause
remains unresolved. Do not claim a demonstrated inheritance defect or an already-fixed report.

Live and archived planning records were searched for an existing memory-repair owner immediately before creation;
none was found. TASK-00149 owns the historical evidence, not this repair. Hosted issue/PR ownership was not queried.
