# Record and inspect typed activity execution facts

## Outcome

Trusted instrumentation can retain safe typed tool/process target, timing and result facts in Common's canonical
activity observations, and currently authorized callers can inspect those same facts through the shared Query and
existing MCP Tool. Unknown/partial evidence stays explicit; no telemetry result establishes business success.
This complete recording-to-inspection slice normally owns one PR and implements the approved pre-v1.5 amendment
in [TICKET-00056](../tickets/00056-TICKET.md), not a new observation service or Agent OS adoption.

## Scope

In scope:

- Optional cohesive execution facts on `Domain\Mcp\Activity\PhaseActivity`, using final readonly ValueObject types
  with validated construction, equality/hash, deliberate structured JSON and exact canonical reconstruction.
- Bounded safe operation target, precision-preserving known start/end, independently measured nonnegative elapsed
  duration and explicit observed call/process result, including unknown values and partial endpoint pairs.
- Existing `Observation::forActivity()` → `RecordPhaseObservation` → handler/recorder → actual DBAL persistence and
  reconstruction, with complete new facts included in immutable comparison and retained identity/retry behavior.
- Existing `ListPhaseActivity` → safe `ActivityView` → final `ListPhaseActivityTool` (`execution.activity`), with the
  bounded strict output schema and actual guarded HTTP projection updated in the same change.
- Default/configured execution-table compositions and meaningful SQLite/MySQL/PostgreSQL behavior/failure evidence.
- Public contracts, limits and before/after caller examples in affected execution guides, README, CHANGELOG and
  CONTEXT.md. Describe proposed versus implemented behavior accurately; no invented release date/version entry.

Out of scope:

- Automatic producer capture, comprehensive MCP/bus instrumentation, global sequences/spools, guaranteed event
  replay, a second mirrored observation ledger, new buses or private handler invocation.
- Transaction API expansion/participation callbacks, nesting around package Commands, required audit orchestration,
  durable external-effect intent or a new outbox/publication guarantee.
- Workflow state/acceptance, application Commands/Queries/Events, process/request attribution, stable snapshot/cursor
  history, normalized/corrected accounting, estimates, budget policy or richer active/queue/wait timing categories.
- General Artifact links/holds, transcripts, new protected capture kinds, generic safe-metadata purge/redaction,
  permanent tombstones, retention orchestration or stronger physical-erasure claims.
- Tool subclasses/copies, Common permission attributes, Access Control dependency/binding implementation, new Tools,
  release certification, tagging, consumer manifest/lock changes or concurrent TASK-00201/00202 work.

### Accepted caller contract

Use `Domain\Mcp\Activity` for the new cohesive values. The approved factory/accessor design is:

| Type | API addition | Meaning |
|---|---|---|
| `PhaseActivity` | Append `?ActivityExecution $execution = null` to `create()`; add `execution(): ?ActivityExecution` | Optional typed activity execution, not a new observation aggregate |
| `ActivityExecution` | `fromParts(?ActivityTarget $target, ActivityTiming $timing, ActivityResult $result): self` | One replaceable whole joining the operation facts |
| `ActivityTarget` | `fromStrings(string $capability, string $name): self` | Safe capability/name, never arguments, a shell command, path or raw Resource URI |
| `ActivityTiming` | `fromParts(?ObservationOccurrence $startedAt, ?ObservationOccurrence $endedAt, ?Duration $elapsed): self` | Independently known producer timestamps and measured elapsed time |
| `ActivityResult` | `unknown()`, `returned()`, `threw(string $failureKind)`, `exited(int $exitCode)`, `cancelled()` returning `self` | Actual observed boundary result, not business outcome |

Reuse existing `ObservationOccurrence` and `Duration`; do not create parallel timestamp/duration/identity bases.
Each new value owns meaningful typed accessors, closed structured encoding/decoding, validation and canonical
comparison. Exact nested wire keys remain implementation design within these semantics and must be documented
and covered by independently expected public output. No raw options array replaces these cohesive arguments.

Existing capture and Command dispatch remain:

```php
$activity = PhaseActivity::create('agent-os/tool', 'Tool invocation returned');
$observation = Observation::forActivity(
    $sourceObservationId,
    $trustedProducerId,
    $sessionReference,
    $phaseReference,
    $occurredAt,
    $activity
);
$commandBus->execute(new RecordPhaseObservation($observation));
```

After implementation, callers can replace only activity construction:

```php
$activity = PhaseActivity::create(
    'agent-os/tool',
    'Tool invocation returned',
    execution: ActivityExecution::fromParts(
        ActivityTarget::fromStrings('tool', 'read'),
        ActivityTiming::fromParts($startedAt, $endedAt, $measuredElapsed),
        ActivityResult::returned()
    )
);
```

Here timestamps are existing `ObservationOccurrence` values or null; `$measuredElapsed` is an existing `Duration`
value or null. `$sourceObservationId` is the stable UUID for this source fact, not regenerated on retry. Separate
start and terminal submissions have separate immutable identities; do not overwrite a started fact with completion.
The producer's actual invocation relationship remains consumer attribution, not an identity inferred from text.

The existing `ListPhaseActivity` Query and `execution.activity` Tool expose this value under `activity.execution`.
An omitted execution value returns explicit null, not guessed zero duration or a successful result. Keep top-level
activity Observation start/end null and outcome unknown; latest session/phase state readers must still exclude
activity/detail facts. Generic observed execution results are intentionally distinct from `ObservationOutcome`.

### Transaction, retry and lifecycle invariants

Reuse Common's existing recording-owned commit and serialization boundary. Optional capture/application-derived
state may use committed event → application policy subscriber → configured CommandBus → secondary Command, with
independent transactions. Demonstrating that composition must not add a transaction around package Commands or
require successful optional delivery before the owning business operation succeeds.

Required audit, safety restrictions and required durable intent retain their owning operation's guarantees.
A post-commit subscriber alone is not required reference/hold participation or a late-write/disclosure fence.
Common admission/read ports still accept the consumer's actual current decisions; this TASK grants no additional
lifecycle coverage. Missing/delayed observations are permitted and never infer business outcomes, zero usage or
continuous active time. Do not implement an Agent OS subscriber/projection graph as part of this package TASK.

Preserve admission before retained lookups, exact submitted-content conflicts, immutable receipt time, no retry
redispatch, confirmed rollback versus uncertain storage failure, and `CommittedObservationDispatchFailed` after
real commit. The safe event remains reference-only; do not add execution facts, summary, usage or private content.

Body removal still retains safe identity/activity evidence, and matching old detail retries still raise
`ProtectedContentRemoved` without comparison/restoration of removed bytes. Purging safe identity ends deduplication;
there is no permanent tombstone. Keep missing detail availability separate from known removal/redaction reasons.
No removal event is added. Removing bodies does not redact safe summaries, execution metadata or application copies;
unsupported lifecycle coverage must stay denied/held, not advertised as complete removal.

## Validation and permissions

- Reuse the existing bounded `ObservationReference` grammar for each target capability/name and selected failure
  kind (1–128 ASCII reference characters), rather than admit free-form URLs, paths or exception messages. Structural
  acceptance is not universal secret detection; consumers select safe source values before constructing them.
- Preserve null endpoints and source precision; reject supplied reversed endpoints and negative elapsed duration.
  Zero measured duration is valid. Keep elapsed independent of wall endpoints: do not derive missing values, clamp
  clock discontinuities, invent precision or require independent monotonic/wall measurements to match. A producer
  unable to qualify a measurement omits it instead of supplying fabricated complete timing.
- `returned()` confirms a call returned, not committed state or durable publication. `threw()` requires a bounded
  safe failure classification, not a Throwable/object dump. `exited()` retains the supplied native integer exit
  code without inferring Workflow success. `cancelled()` requires actual observed cancellation, not merely intent.
  Reject result-incompatible fields and unknown representations; absent execution/result remains explicit.
- Preserve existing activity summary/usage limits, complete encoded response bounds and fixed safe failure behavior.
  New nested schemas remain closed; do not weaken `additionalProperties`, drop validation or truncate facts to fit.
- Existing current producer/project/session/phase recording admission, execution read access, activity grants,
  reference grants and separate protected-body/removal permissions remain independent. Value construction, target
  names, source IDs and successful optional capture confer none of them.
