# Establish the presentation destination and ownership

**Labels:** `wayfinder:grilling`, `wayfinder:domain-modeling`
**Mode:** HITL
**Status:** Closed
**Map:** [Fight Common Documentation Presentation](../fight-common-documentation-presentation-map.md)
**Depends on:** —

## Question

What is the presentation program's destination, which surface is primary, and how should the Fight identity
relate to Fight Common and John's GitHub profile?

## Must decide

- which repository or profile owns the primary product experience;
- whether the identity is package-specific or reusable across the Fight family;
- which secondary surfaces receive adaptations;
- whether the work may alter Fight Common's PHP public API; and
- which delivery effects require later, separate approval.

## Resolution boundary

This ticket fixes destination, ownership, identity hierarchy, and approval boundaries. It does not select an
audience promise, visual language, logo, page direction, renderer, content rewrite, or implementation slice.

## Resolution

Fight Common documentation and the repository README are the primary product. The identity will begin with a
reusable Fight family mark and a Fight Common lockup so later Fight projects can share the family without losing
their own product names. John's GitHub profile receives a constrained adaptation that showcases the open-source
work; it is not an independent brand or site.

This presentation program changes no PHP public API. Wayfinding, implementation, commit, push, pull request,
deployment, profile publication, and cleanup remain separate approvals.
