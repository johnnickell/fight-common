# Framework Portability and Starter Projects

## Destination

Provide one idiomatic, documented, and tested composition of every important Fight Common Application
contract for Symfony, Laravel, Yii 3, CodeIgniter 4, and Slim while preserving framework-neutral Domain and
Application layers. Repair Fight Common's `1.2.0` compatibility envelope additively, extract shared access
control into its own public package, and hand each starter project an implementation-ready contract.

## Decisions

- Fight Common remains the temporary umbrella planning authority until each new public repository exists and
  adopts its own implementation plan.
- Fight Common `1.2.0` preserves published `1.x` contracts, adds capability-first framework-qualified adapter
  paths, and reserves incompatible cleanup for `2.0.0`.
- Framework support is measured by complete consumer journeys and verified compositions, not equal numbers of
  framework-branded adapters.
- Each starter owns one opinionated, replaceable default stack and one complete editable client application.
- Exact framework ranges and proposed shared adapters require isolated and combined dependency evidence plus
  walking-slice proof before implementation is authorized.
- Accepted Wayfinder decisions are synthesized into permanent PRDs and linked back to their source tickets.

## Scope

Fight Common contract repair and compatibility certification; exact supported framework lines and capability
compositions; the Fight AccessControl extraction and authentication model; persistence and transaction walking
slices; five starter-project handoffs; and the shared governance, documentation, client, and release boundaries
needed to implement those repositories safely.

## Out of Scope

Implementing adapters or starter projects in this planning change; forcing implementation-mechanism parity;
opening proprietary consumers; publishing packages or repositories; and deleting supported `1.x` contracts
before the `2.0.0` boundary.
