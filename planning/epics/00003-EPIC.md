# Deterministic Release Coordination

## Destination

Provide Fight Common with a deterministic, approval-gated release-coordination system for normal
releases, supported-line maintenance, patching, publication, and recovery. Repository commands own
policy and evidence; operator skills and the runbook route and explain the commands.

## Decisions

- The implementation is divided into four PRDs: deterministic release foundation; release lifecycle;
  maintenance and patch workflows; and operator surfaces and integration.
- The first proving slice is a normal `develop` feature journey through plan, package, and certify.
- Git, signing, GitHub, and Packagist boundaries use explicit ports, deterministic fakes, and contract
  tests. Real external checks remain separately authorized operator work.
- Each executable ticket has its own branch from `develop`, passes the composed offline gate, and does
  not require real publication for completion.
- Implementation proceeds from foundation to normal release, certification, publication recovery,
  maintenance, patching, and finally operator surfaces.
- Accepted Wayfinder decisions are synthesized once into their permanent planning home and linked back
  to the closed Wayfinder tickets.

## Scope

The six planned release skills, one `bin/release` command surface, durable plans and runs, evidence
manifests, compatibility certification, deterministic archives, GitHub and Packagist verification,
maintenance-line workflows, operator routing, CI integration, and the release runbook.

## Out of Scope

Implementing the release system in this planning change; provisioning signing or hosted environments;
publishing a release; changing tags, branches, GitHub, Packagist, or consumer repositories; and
duplicating release policy in skills, CI YAML, or agent instructions.
