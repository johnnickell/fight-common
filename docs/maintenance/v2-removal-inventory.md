## Verification and migration boundaries

Packagist source references agree with the released commits `a2cd615d9b5064c9c30e994655536176249cd73b` (v1.2.0),
`87b9580c072f3149d574e09865daa79620c92118` (v1.4.0), and `06fb5cd3720af9cf8295198f74040d95b64c5155` (v1.5.0).
[ADR 0011](https://github.com/johnnickell/fight-common/blob/develop/planning/adr/0011-non-structural-compatibility-policy.md)
requires one actually released minor; v1.5.1 is the comparison baseline, not a second required deprecation window.

- MCP canonical names now own the actual declarations. New native frames use the canonical class and private
  property scopes. Retain explicit array/JSON protocol formats; don't deserialize old native frames against the new
  classes without a planned conversion. Do any trusted export/drain with the old version loaded before changing versions.
- Public-read removal also changes reflection, generic object enumeration and native JSON property projection.
  Use the typed getter or an existing explicit wire projection, not a generic object cast. Keep constructor
  argument names as documented. Migrate persisted object state before mixing old and new workers.
- Safe HTTP is explicit framework composition, not simply a namespace rename. The intermediate Symfony exception
  names under `Adapter\Http\Symfony` were the 1.x migration path; they are also removed in 2.0. Follow the
  [Symfony wiring](../safe-http-errors.md#symfony-native-exception-lifecycle) to replace the old controller and listener,
  configure redacting diagnostics, and keep the separate validation subscriber where used. In Laravel, keep the
  response provider and bind the safe exception handler if you were using the old exception path. Recheck negotiated
  JSON/HTML, status and redaction.
- Do not alter DBAL type names or table data as part of this library upgrade. Selection-based table names come
  from the same selection passed to the schema and repositories. Moving a live table requires a separate consumer
  operation and recovery plan; this package upgrade moves no data.

## Representative consumer checks

Read-only source checks found old MCP fixture imports in Fight Access Control tests and a `PsrCache` class ID in
Fight Agent OS's cache configuration. Move those imports and that registration to the exact replacements above
before those projects adopt 2.0. Their current Composer constraints still select 1.x; no consumer source,
installed dependencies, queues or stored data were changed. The source check cannot prove that saved PHP objects
are absent or that a complete application upgrade will pass.

## Excluded

Strict Pagination and ResultSet construction belongs to TASK-00227. Root MCP Responder and Diagnostics, Domain serializer interfaces, Standards, native ORM mappings, Doctrine type-name constants and dependency floors are not deprecated by this inventory.
